# 交付与一致性校验

## 文件组织

尊重用户指定输出目录；未指定时使用目标项目内明确命名的方案目录。先总后分，多文件且职责单一。以下为推荐结构，可随项目规模合并或拆分，但所有要求均须覆盖：

```text
design/
  index.md                 # 封面、内容目录、交付目录树
  architecture.md          # 总体方案、架构图、异步时序图
  modules/<module>.md      # 每模块职责、契约、业务流和验收
  api.md                   # 服务端接口
  permissions.md           # 主体定义、权限矩阵与数据隔离
  errors.md                # 全局错误码表
  states.md                # 状态模型与转移图
  data.md                  # 数据字典
  product.md               # 产品端、页面边界、页面流转与原型说明
  ui.md                    # UI 规范：色彩、间距、字体、布局、动效、文案、无障碍、国际化
  components/basic.md
  components/composite.md
  components/business.md
  components/pages.md
  acceptance.md            # 系统最终验收及追溯表
  glossary.md              # 分开列业务名词与技术术语
  review.md                # 实际校验结果、假设与待确认项
  web/                     # 由 Markdown 构建生成，不手工编辑
```

单个 Markdown 文件超过约四百行或出现新的职责域时拆分；模块多的项目按领域分目录，避免交付一个巨型 `modules.md`。

Markdown 是唯一内容来源。HTML 阅读页必须由 Markdown 构建生成，禁止手工维护第二份正文：选用项目已有环境里现成的 Markdown 静态站点或文档生成工具（如 markdown-it 模板、mdBook、VitePress、Docsify、Sphinx 等任选其一），生成物须能直接以 `file://` 打开且不依赖网络。生成后不得手改 HTML，任何改动都回到 Markdown 重新生成并再次构建。所用工具、版本与构建命令记录在 `index.md` 或方案目录的 README 中，保证他人可复现。

章节编号与锚点一次定稿：标题采用“编号 + 英文 slug”，如 `## 3.2 Permission Matrix`，锚点由工具按标题生成，正文内部链接与阅读页深链指向同一锚点。已发布章节的编号与 slug 不因措辞调整而变动；确需重命名时同步更新全部引用并在 `review.md` 记录影响范围。文件拆分后不要用“见其他章节”代替所有实质内容，引用必须精确且可访问。

## HTML 阅读体验

- 导航、目录、折叠、深链与搜索由生成工具或模板提供，不手写脚本；视觉风格清晰简洁。
- 默认离线可用：样式、脚本、字体与图全部本地化。Mermaid 图在构建时预渲染为内联 SVG 或本地资源，并保留一份折叠的图源码；禁止运行时从 CDN 拉取渲染。确需外部资源时必须声明网络依赖，不声称离线可用。
- 资产只存实际使用的内容：图片、图标、字体、媒体统一放 `web/assets/`，图标与插画一律 SVG 并优先内联；禁止 emoji 充当图标；每个资产标明来源与授权，未使用的资产不入库。
- 桌面左侧导航，当前章节高亮，点击直达；窄屏可收起导航。
- 总览、核心结论默认可见；大段细节放入有摘要标题的折叠区域。深链接跳转时自动展开目标所在折叠区域，支持刷新定位和前进后退。
- 渲染完整正文、表格、代码；表格与长代码横向滚动，图可放大查看，不溢出布局。
- 支持键盘导航、可见焦点和清晰层级。原型演示中的按钮与跳转应有可观察的演示反馈，使用静态样例与展示状态，不接入真实请求、鉴权或持久化，不把原型做成第二套业务实现。
- 阅读页面与产品原型须清楚区分：原型为独立静态文件，可从阅读页链接，不隐含发布或部署授权。

## 假设与待确认

方案中每一条自行设定的假设与未确认事项都进入 `review.md`，统一格式：编号、内容、默认取值、影响章节、确认后需重做的部分。影响核心边界且尚未确认的，在正文对应位置就地标注待确认，不能只在附录提一句。

## 交付前校验

按实际内容逐项核对并修复问题，在 `review.md` 记录已验证、未验证和待确认项，不将“设计已描述”当成“系统已通过验收”。

1. 覆盖性：每个模块、产品端、页面和组件都已展开；每项需求均有设计归属及最终验收项。四态、微文案、无障碍与国际化须落实到具体页面条目，不能只写在规范里。不适用的规范条目已在对应章节写明不适用及依据，不是静默省略。
2. 架构一致性：模块清单与图节点一致，依赖方向和数据归属一致，无重复职责或无来源的关键数据；异步推进与补偿流程有时序图。
3. 契约一致性：实体名、字段类型、状态枚举、抽象方法、伪代码、请求和响应一致；每个业务组件调用的接口均存在且具备相应权限。接口的权限判定与权限矩阵逐行对应，错误语义引用全局错误码而不各自定义，字段定义与数据字典一致。
4. 流程完整性：主流程、失败路径、跳转与状态变化互相对应；URL 初始化、更新、刷新和前进后退逻辑完整；状态转移图中合法与非法转移均有标注并与错误码一致；主体切换后的失效路径完整。
5. 表达合规：受限架构段无技术栈、源码引用或项目名；验收不分期；业务名词和技术术语分开解释；无未替换模板或空伪代码。业务设计全部为表达清楚所需的最简伪代码，基础组件不写实现，复合组件说明组件组合，业务组件说明组件与接口各自用途，页面保持薄封装；HTML 展示代码不夹带业务实现。
6. 文件一致性：链接与锚点有效，编号与 slug 唯一且未漂移。HTML 由 Markdown 构建生成且未手改；抽查至少三节的结论句与 Markdown 逐字一致，没有只有 HTML 才有的关键设计结论。
7. 追溯完整性：追溯表四列填满，每个需求至少一个验收项，没有孤立需求或孤立验收项；无法对应的行已标注原因。
8. 展示验证：断网状态下打开阅读页，检查导航、折叠、深链接、刷新、窄屏、键盘交互、图渲染与原型核心路径；微交互在减少动态效果偏好下降级生效，动画结束后 DOM 与状态一致，不停在中间帧；目标语言下文案不溢出、不截断关键信息。缺少运行环境时说明未实测范围，不能声称通过。
9. 资产合规：无 emoji 充当图标或状态标记；图标与插画为 SVG 且可随主题换色；图片有宽高比与替代文本，装饰图置空；视频有封面帧与字幕或文字稿，音频有文字稿；自定义滚动条保留可见滑块与键盘操作；媒体文件不为唯一信息载体。

最终答复提供 Markdown 总入口与 HTML 入口的可访问链接、输出位置以及尚未解决的实质问题。不要只提供工作说明而不生成文件。
