# UI 与组件设计

## UI 规范

- 标准色：给出实际色值和语义令牌，覆盖品牌、背景、表面、正文、边框、成功、警告、错误、禁用和焦点；状态不能只依赖颜色表达。
- 间距：以 `4px × n` 为常规尺度，逐级解释信息亲疏关系，如同一控件内部、相关字段、组件组、页面区块；统一内边距与外边距的用途。
- 字体：定义字体族及回退、字号、字重、行高、颜色，区分页面标题、区块标题、正文、辅助文字、标签和数据；明确长文本换行与省略行为。
- 布局：定义内容宽度、栅格、边距、导航、固定区域、滚动容器、断点和窄屏布局。写清表单、列表、详情与弹层的布局规则及键盘焦点行为。
- 微交互：给出时长与曲线的语义令牌最小集合（如快、常规、慢及标准、进入、离开曲线），说明哪些是微交互可用的范围；列出减少动态效果偏好下的统一降级规则；禁止无降级分支的位移和阻塞交互的动画。
- 微文案：定义按钮动词、错误提示、空态、确认弹窗与成功反馈的写法。错误提示说明发生了什么、为什么、下一步做什么；按钮使用明确动作而非“确定”一类泛称；空态说明用途并给出下一步；确认弹窗写清对象与后果。术语引用统一命名清单，不在各页面另造同义词。
- 无障碍：给出文本与背景的对比度下限、焦点可见样式与焦点顺序、跳过导航、图标按钮的可访问名称、表单错误与字段的关联方式。关键路径可仅用键盘完成，状态变化须有非颜色的提示。
- 国际化：列出目标语言、允许的文案长度浮动（按最长语言预留约三成）、复数与性别规则、日期时间数字货币的格式来源与统一格式化入口、字体回退与断行规则。布局不得依赖固定文案宽度，按钮与表头须定义最小、最大宽度及截断或换行行为。
- 图标与插画：一律使用 SVG，禁止用 emoji、符号字符或位图冒充图标，也不以 emoji 充当状态与优先级标记；Mermaid 图中的语义符号按绘图技能规范处理，不在此禁令内。图标须自包含、可用 `currentColor` 换色，给出尺寸档位（如 16/20/24）与统一线宽基准；装饰性图标标记为对辅助技术隐藏，承载语义的图标给可访问名称。空态与错误插图同样使用 SVG，不引入无法随主题与语言变化的位图。
- 图片：声明用途（内容图、背景、插图）、宽高比与尺寸区间、各断点下的裁切规则、密度倍数与响应式候选来源、格式优先级（矢量优先，位图给现代格式与回退）；给出替代文本规则（内容图描述信息、装饰图置空）、懒加载与首屏优先加载的界限、加载占位与失败回退。禁止用图片承载必须可搜索、可翻译或需随主题变化的文本。
- 视频与音频：默认不自动播放；确需自动播放时必须静音、可暂停并遵循减少动态效果偏好。给出封面帧、预加载策略、字幕与文字稿、时长与体积上限、播放控件与键盘操作、不支持格式时的降级内容、离开视口是否暂停。媒体不得作为唯一的信息载体，关键信息须有文字等价物。
- 滚动条：说明是否自定义样式、在主流浏览器的降级表现，以及是否影响布局宽度。自定义滚动条须保留可见滑块与足够命中宽度，不得隐藏滚动条却仍要求使用滚轮发现内容。区分页面滚动与局部滚动容器，声明嵌套滚动的处理、内容变化时的滚动位置保持、回到顶部的规则，以及 PageUp、PageDown、Home、End 的键盘支持。
- 主题：给出明暗主题的令牌映射关系，说明图片、插图、阴影与半透明层的双主题变体；系统偏好跟随与手动覆盖的优先级、切换时机与是否持久化；切换过程中不得出现整页闪烁或对比度不达标的中间态。

以上条目按项目实际情况取用，不要求逐条堆砌。确实不涉及的能力（例如无媒体、无多主题、无自定义滚动条）在 UI 规范中写明不适用及依据，不虚构内容；已经涉及的能力必须给出具体取值与规则，不得只写“按规范执行”。取舍由设计者结合项目现状判断，判断结果须在文中可见。

## 组件层次

各层先列完整组件清单，再逐个定义组件名、用途、输入 Props（类型、必填、默认值）、事件及交互状态。优先复用项目已有组件库；未选组件库时定义能力和适配接口，不为方案任务另造通用组件库。伪代码展示组合及交互即可，无需重新实现库内部细节。

组件伪代码只写在围栏内，围栏标 `tsx`/`ts`；`.md` 中不写 JSX 组件标签，不依赖 `title=` 元信息。

### 基础组件

只负责样式和交互，不获取业务数据、不绑定领域权限。定义组件名、输入 Props、尺寸、变体、禁用、焦点、加载和错误等适用状态，以及受控值与事件回调。优先使用现成组件库，不写组件实现；仅用最简调用或事件伪代码表达如何使用组件、交互逻辑和 UI 规范的应用。图标、标签、分隔线、滚动容器等原子元素也在此层给出统一契约，尺寸与颜色只能引用令牌。

微交互指由单一用户操作触发、时长极短、只反馈操作已被接收的即时响应，典型包括悬停与聚焦态、按钮提交中、开关与展开折叠、勾选、骨架到内容、复制确认与拖拽抬起。每个具有交互的基础组件须声明：触发条件、变化的属性、时长与曲线、是否可中断，以及减少动态效果偏好下的降级（降为透明度变化或直接跳变）。反馈不得改变元素占位造成布局跳动；时长取自动效令牌，不写死毫秒数；动画只做反馈不承载业务状态。

### 复合组件

由多个基础组件构成，重点定义布局、插槽、对齐、响应式行为和组件间交互；仍不承担业务数据获取。明确输入 Props 和组件名，优先复用现成组件库，用最简组合伪代码描述使用哪些组件、如何排列和如何传递事件，不展开组件内部实现。组合中的子组件微交互须节奏一致：同一区域内同时触发的过渡共用同一时长与曲线，避免出现有的即时有的缓慢。

### 业务组件

组合基础、复合或其他业务组件，绑定数据和状态。逐个写明使用的接口标识、方法、路径及字段映射，以及加载、空、失败、重试、无权限、提交中和提交后反馈等适用状态。处理重复操作及请求竞态；避免旧响应覆盖新筛选结果。

使用最简 TSX 伪代码，明确“使用哪些组件、调用哪些接口、各自完成什么事情”，展示数据及状态绑定和用户操作后的反馈，不写实际请求客户端、业务算法或组件内部实现。所有回调、数据服务与类型都有定义或明确契约来源。例如用户选择器、附件选择器、组织选择器只在项目需要时纳入，不把示例视为必选功能。

interface EntitySelectorProps {

  disabled?: boolean;

export const EntitySelector: React.FC<EntitySelectorProps> = (props) => {
  // 在实际方案中展开查询接口、加载/失败/空态和选择回调逻辑。

### 页面组件

页面是业务组件和基础组件的薄封装，负责路由参数、组件组装和页面级交互，避免重复编写业务请求逻辑。逐页面给出组件名、Props、布局及最简 TSX 伪代码，并对应产品端的页面清单；伪代码展示组装、传参、初始化及状态同步，不写具体业务实现。

初始化可分享、可恢复的页面状态必须来自 URL search params：筛选、分页、排序、标签、选中记录或步骤等。明确字段名、类型、默认值、非法值处理、编码方式；交互时同步 URL，前进、后退、刷新后恢复一致。说明何时 replace、何时 push，以及筛选改变是否重置分页。

“刷新不丢状态”要逐项落实：适合 URL 的状态写入 URL；草稿或其他不能放 URL 的状态选择合适持久化机制，并说明恢复优先级、有效期及清理时机。密码、令牌或敏感内容不放 URL。服务端数据按恢复后的参数重新获取，不把所有服务端数据序列化到 URL。

每个页面须给出加载、空、失败、无权限四态的表现与默认动作，以及部分可用（部分区块取数失败）的降级方式，不能只画成功态。空态区分“尚无数据”与“筛选无结果”，并给出清除筛选或创建入口；失败态给出重试与返回路径，重试保持当前筛选与分页；无权限不得用空白代替，须说明原因与申请入口。

页面还须给出路由与弹层的转场规则，以及转场与状态恢复的先后：刷新和前进后退可重放转场但须幂等，不因播放动画改写 URL 或重复请求，视觉位置恢复优先于进场动画。

后台任务、消息中心、表格加弹框表单、详情、多步表单、趋势、监控、个人中心、配置中心等只是候选页面类型，按实际项目选用。

## 可用性自检

界面设计完成后，按 Nielsen 十大启发式逐条过一遍：问题按严重度分级，并回写到对应页面条目与验收项；只留在评审记录里视为未执行。启发式自检的清单、严重度判定，以及任务测试、标准化量表与上线后行为数据的方法选择，见 [可用性检查与指标](usability.md)。

本文件定义界面应该长什么样，可用性章节定义怎么验、达到什么数才算过。规范写得再全也不能替代实测。
