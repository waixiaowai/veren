### UI规范设计

- 设计标准色
- 间距的视觉含义，一般为4px * n，n代表信息亲疏关系
- 字体字号字体颜色
- 设计说明布局规范
- 动效规范：时长与曲线令牌、层级规则、降级策略
- 微文案：按钮动词、错误提示（发生了什么/为什么/怎么办）、空态、确认弹窗、成功反馈
- 无障碍：对比度下限、焦点可见与顺序、跳过导航、图标按钮可访问名称、错误与字段关联
- 国际化：目标语言、文案长度浮动预留、复数与格式、字体回退与断行、不依赖固定文案宽度
- 图标与插画：只用 SVG，禁止 emoji 与符号字符充当图标，给出尺寸档位、线宽与可访问名称
- 图片：用途、宽高比、裁切、响应式候选、格式与回退、替代文本、懒加载与失败回退，不用图承载文本
- 视频与音频：默认不自动播放，封面帧、字幕或文字稿、体积上限、控件与降级内容，媒体不作唯一信息载体
- 滚动条：是否自定义及降级，保留可见滑块与命中宽度，嵌套滚动、位置保持与键盘翻页
- 主题：明暗令牌映射、图片与插图变体、跟随系统与手动覆盖的优先级、切换不闪烁

### 组件设计

#### 基础组件设计

设计基础组件列表，只负责样式和交互，伪代码实现，定义好交互逻辑和UI设计，定义输入Props及组件名，一般使用现成的组件库不重复造轮子，不写实现

#### 复合组件
设计符合组件列表，将多个基础组件组合成复杂的合成组件，定义好交互逻辑和布局设计，核心是布局，定义输入Props及组件名,一般现成的组件库不重复造轮子，伪代码描述用哪些组件

#### 业务组件设计

业务组件列表，负责将多个(基础/复合/业务)组合组装+数据及状态绑定，伪代码实现，伪代码实现，定义好交互逻辑和注重用户体验，用那个接口获取数据，如：用户选择器、附件选择器、组织架构选择器等，定义输入Props及组件名，伪代码，描述使用哪些组件、哪些接口干什么事情

```tsx
export const DemoComponent: React.FC<{}> = (props: DemoProps) => {
    // 伪代码
}
```

#### 页面组件设计

页面是业务组件+基础组件的薄封装，负责组装业务组件形成页面，伪代码实现，定义好交互逻辑，刷新页面状态不丢，初始化数据从 url search params中获取；定义路由与弹层转场，及刷新后状态恢复与动画的先后关系
如：后台任务/消息中心/表格+弹框表单/详情页/多步表单/统计趋势/监控分析/个人中心/配置中心等等，定义输入Props及组件名，伪代码
每个页面须给出加载、空、失败、无权限四态，以及部分可用的降级；空态区分无数据与筛选无结果，失败态给重试并保持筛选与分页

## 输出形式
- Astro 站点优先：Markdown 直接导入 `src/content/docs/design/` 即可构建；需要离线阅读页时再由同一份 Markdown 生成
- 每个文件顶部写 frontmatter（title/description/sidebar/draft/lastUpdated），正文不写 H1
- 章节标题固定“编号 + 英文”，不写 `{#id}`；锚点按 github-slugger 规则自动生成
- 站内链接写 `/design/<id>/#<anchor>`，不写 `.md` 相对链接
- Mermaid 先渲染成 SVG，用 Markdown 图片引用，源码放 `<details>`
- 图片用相对路径，禁止远程图与 `<img>`；不用 emoji 充当图标
- 生成 Markdown 文件保存整个方案，适当分级、分段、分文件
- 总体叙事，先总后分方便阅读
- 多文件输出，保持文件职责单一
- 禁止写具体的业务代码，全部是伪代码，能表达清楚的情况下最简
