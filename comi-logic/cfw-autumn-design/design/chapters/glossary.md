本章分两部分：业务名词用于统一产品、接口与页面中的叫法；技术术语只解释本方案实际使用的概念。两者不混用，正文出现的状态名与实体名以此表为准。

## 1. Business Terms

| 中文名 | 统一标识 | 解释 | 易混边界 |
| --- | --- | --- | --- |
| 组织 | `organization` | 数据归属与计费隔离单位 | 不等于登录账号；一个账号可属于多个组织 |
| 环境 | `env` | 组织内的数据分区，取值为沙箱或生产 | 不等于部署环境，同一部署同时承载两种环境 |
| 客户 | `customer` | 被计费的业务主体 | 不等于登录用户；客户由集成方定义 |
| 实体 | `entity` | 客户下的次级主体，如席位、工作区 | 不是独立客户，不能跨客户共享 |
| 功能项 | `feature` | 计量单位或权限位 | 不等于套餐；套餐引用功能项 |
| 计量功能项 | `metered feature` | 可累计用量的功能项 | 与布尔型功能项的差别是不可计量、只判有或无 |
| 信用系统 | `credit system` | 把多个计量功能项折算为统一积分 | 不是支付货币，不可直接提现 |
| 套餐 | `plan` | 可售单元，由权益行与价格行组成 | 与「产品」同义，对外接口沿用产品命名 |
| 套餐版本 | `plan version` | 套餐的一次不可变发布 | 改价不产生新版本，只有已有客户的变更才升版本 |
| 价格行 | `price` | 套餐中的一项收费声明 | 价格行可以没有金额，仅授予额度 |
| 权益模板 | `entitlement` | 套餐对某功能项授予多少、如何重置 | 不等于余额；余额是模板在客户身上的落地 |
| 客户产品 | `customer product` | 客户持有某套餐的一次实例 | 对外常称「订阅」，内部标识固定为客户产品 |
| 客户权益 | `customer entitlement` | 余额实例，记录可用额度与重置时刻 | 与权益模板是一对多关系 |
| 余额 | `balance` | 对外字段名，等同客户权益的可用额度 | 不等于账户余额，不涉及资金 |
| 结转 | `rollover` | 上一周期未用完额度转入下一周期 | 结转过期与实例过期是两件事 |
| 用量窗口 | `usage window` | 滑动窗口内的用量计数 | 不是余额，不参与扣减顺序 |
| 事件 | `event` | 一次用量上报的不可变记录 | 与「回调事件」区分，后者是出站通知 |
| 结算 | `billing` | 购买、变更、续费、退款的总称 | 不包括发票展示 |
| 账单计划 | `billing plan` | 一次结算的计算结果，含金额与动作 | 不是账单；账单是发票 |
| 结算锁 | `billing lock` | 同一客户同一时刻只允许一个结算执行 | 与额度锁定凭证不是一回事 |
| 结算会话 | `checkout session` | 需要用户确认时创建的上下文 | 不等于支付意图 |
| 支付意图 | `payment intent` | 一次支付尝试及其状态 | 一个会话可有多笔意图 |
| 履约 | `fulfillment` | 支付成功后执行业务结果 | 与「支付成功」分离，可重试 |
| 发票 | `invoice` | 与通道发票一一对应的账单文档 | 不是收据 |
| 行项目 | `line item` | 发票中金额的最小不可变单位 | 更正用反向行项目，不修改原行 |
| 迁移 | `migration` | 批量把客户或套餐切换到新状态 | 不等于数据库结构迁移 |
| 作用域 | `scope` | 资源加读写的权限标识 | 不等于角色；角色映射为一组作用域 |
| 秘密密钥 | `secret key` | 服务端使用的机器密钥 | 与可公开密钥的区别是能否写 |
| 可公开密钥 | `publishable key` | 浏览器侧只读密钥 | 不可用于写操作 |
| 失败开放 | `fail open` | 依赖不可用时返回保守默认而非报错 | 只适用于读，写一律失败关闭 |

## 2. Technical Terms

| 术语 | 解释 | 在本方案中的用途 |
| --- | --- | --- |
| 账单计划 | 计算阶段产出的纯数据对象，包含本地动作、通道动作与回滚清单 | 执行与补偿的共同依据 |
| 计划与执行分离 | 计算不产生副作用，执行按计划推进 | 支撑幂等、续跑与回滚 |
| 幂等键 | 客户端或系统生成的唯一标识，用于识别重复请求 | 上报、结算、回调去重 |
| 租约 | 带过期时间的互斥占用 | 结算锁、锁定凭证、迁移领取 |
| 失败开放 | 依赖故障时放行读请求 | 缓存与锁不可用时的降级策略 |
| 补偿 | 对已执行动作的反向操作 | 通道成功而本地失败时的退款与作废 |
| 对账 | 与支付通道逐笔比对并产出差异 | 续费与退款后的状态校正 |
| 归约式执行 | 同一计划重复执行收敛到同一结果 | 断点续跑 |
| 触发器 | 由支付通道回调驱动的状态推进 | 续费与开票 |
| 定时调度 | 按分钟触发的批量任务 | 试用到期、余额重置、悬挂清理 |
| 长任务运行器 | 承载迁移等长耗时作业的外部执行面 | 迁移与缓存预热 |
| 边缘运行时 | 在靠近用户的节点执行请求的运行时 | 接入层与领域层的部署形态 |
| 关系型事实库 | 保存权威状态的数据库 | 状态与金额的唯一事实来源 |
| 连接代理 | 为边缘运行时提供数据库连接的中间层 | 降低连接建立开销 |
| 分布式锁 | 跨实例的互斥机制 | 结算与确认的并发控制 |
| 出站回调 | 系统主动通知集成方的事件推送 | 产品变更与阈值告警 |
| 验签 | 用密钥校验回调来源 | 所有入站回调 |
| 书面契约 | 以类型定义与接口描述固定的约定 | 模块契约与 SDK 生成 |
| 版本协商 | 请求声明接口版本，服务端转换 | 旧版本兼容 |
| 降级 | 依赖不可用时以较弱能力继续服务 | 缓存、队列、锁 |
| 骨架屏 | 与最终内容几何一致的加载占位 | 列表、详情、图表 |
| 减少动态效果 | 操作系统级偏好 | 所有动画的降级分支 |
