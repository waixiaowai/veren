本章是错误语义的唯一来源：接口章只引用码，模块章只抛码，页面章只按码选文案。状态机的转移约束与非法转移对应的失败码在 状态模型 中展开，两章共用同一套码。

## 1. Code Format

统一格式为三段式：域前缀、HTTP 状态码、三位序号，以连字符连接，例如 `BILL-423-001`。域前缀固定为以下取值：`GEN` 通用、`AUTH` 身份、`TEN` 租户、`CUS` 客户、`CAT` 定价目录、`BAL` 额度账本、`BILL` 结算、`CHK` 购买会话、`PAY` 支付通道、`INV` 发票、`EVT` 事件、`MIG` 迁移、`TOOL` 工具链。

规则的三个要点：同一失败在不同接口下必须复用同一码；状态码只表达类别，不用来区分细分原因；序号一经发布不再改变语义，废弃的码保留占位并标注废弃。

## 3. Retry Semantics

只有标注可重试的码才允许客户端自动重试，且必须带指数退避与随机抖动；幂等前提是请求携带幂等键或操作本身按业务键幂等。`BILL-502-001` 的「视情况」判定标准是：通道明确返回可重试错误时重试，明确拒绝时不重试，超时先查询再决定。

## 4. Message Layers

服务端返回的 `message` 是排查用英文短句，与码一一对应；面向终端用户的中文文案在界面层按码映射，不直接展示服务端 `message`。同一码在不同页面允许不同措辞，但不得改变语义与后续动作。

## 5. Illegal Transitions

状态机中所有非法转移必须返回上表对应的码，不允许返回泛化的 `GEN-400-001`：

| 实体 | 非法转移 | 返回码 |
| --- | --- | --- |
| 客户产品 | 已过期实例再次取消 | `GEN-409-001` |
| 发票 | 已作废发票标记支付 | `INV-409-001` |
| 发票 | 超额退款 | `INV-409-002` |
| 结算会话 | 过期后确认 | `CHK-410-001` |
| 结算会话 | 已完成会话再次确认 | 幂等返回首次结果，不报错 |
| 支付意图 | 已失败意图直接置为已支付 | `PAY-409-001` |
| 迁移运行 | 已完成运行再次运行 | `MIG-409-001` |
| 余额 | 已释放凭证再次释放 | 幂等返回已释放，不报错 |
