# notebook 三类笔记生命周期任务（四问加深 v2）

状态：执行中（2026-11-02 立项）
关联：`docs/notebook-zettelkasten-design.cn.md`（rc.1 设计，其"写入时纪律"决策本文将复核）、`docs/notebook-roadmap.cn.md`（M1–M5）

## 0. 第一性原理（全局裁决标准）

> 你学习和收集的东西越多，你的笔记就会越有用，就会有越多的想法组合在一起，并激发新的想法，也就越能轻而易举地写出一篇精彩的文章。

这是 Ahrens 卡片盒法的第一性原理：**卡片盒是复利机器**。本任务的一切设计决策以飞轮为准绳：

- **分类是进料管理，不是管理学整洁。** 闪念=进料口（快速收，价值未定）；永久=化合产物（只进不退，越攒越值钱）；项目=在制品（结项时蒸馏回流，飞轮不许价值滞留在死项目里）。
- **闪念"一两天扔掉"的合法前提是价值已转移**（已炼成永久卡）——trash 是化合后的滤渣处理，不是定时清理。
- **M5 出口（从盒到文）不在本任务范围**，但分类设计不得堵死出口（永久卡的形态必须可直接组装成文章骨架）。
- **飞轮是否有转，用数字裁决**（见 §6 仪表），不由实现者自辩。

## 1. 现状取证（2026-11-02 检查结论）

- `NoteRecord`（`plugins/notebook/src/types.ts:54`）只有 `id/owner/title/body/createdAt/updatedAt`，无分类字段。
- "分类是查询不是 schema"是既定立场（`graph.ts` `staleView` 注释原话）；`staleView`（无入链且超 `STALE_DAYS=7` 天）是唯一生命周期信号。
- "不分类"是设计文档显式决策（`notebook-zettelkasten-design.cn.md:197`）：纪律从复习时移到写入时（一卡一想法 + 链接必须已存在）——该立场**事实上站在 Matuschak evergreen 一侧**，与 Ahrens 闪念/永久流水线存在立场冲突，本文 §3 显式裁决。
- 全源码无 fleeting/永久/项目分类痕迹；`delete_note` 被引用时拒绝（card-referenced）；无回收站、无 TTL。

## 2. 任务

把 Ahrens 的笔记分类落成**带终局动作的生命周期**，不是加标签字段。七条腿：

1. **取证先行（禁先写码）**：对照阅读 Ahrens 四类笔记原章（中译《卡片笔记写作法》+英文原本 *How to Take Smart Notes*），逐字提取每类不变式（存放地/寿命/写入纪律/终局动作），产出不变式表（§3）；飞轮章节一并取证。读 Matuschak evergreen notes 反方立场与卢曼本人实践，写明本插件现行"写入时纪律"实际站哪边。用户口径三类（闪念/永久/项目），Ahrens 四类（多文献笔记，其锚=书目信息，本插件不存在）——三还是四，裁决判据：**飞轮需不需要独立的"阅读进料"状态**。
2. **裁决"扔"的语义**：闪念终局=「promote 成永久卡 **或** 显式 trash（前置=价值已转移：可落地为该卡无未被消费的出链价值）」，不是 TTL 定时删除。现行 `STALE_DAYS=7` 待加工区与闪念窗口的关系（替代/共存/改名）一并裁决。
3. **状态机与双入口**：三类=状态，转移=显式工具动作（promote/trash/archive，各带前置条件）；闪念入口放宽现行写入纪律（链接可未解析、无标题纪律）。一个工具带 kind 参数 vs 两个纪律不同的工具，取证后裁决。项目笔记先取证 task-workbench 的 Task/TaskTarget，无锚则砍掉并写明，禁止空标签；若保留，结项蒸馏回流（archive 前置）是硬要求。
4. **schema 裁决**：按类决定显式列 vs 派生，允许混合；改 `NoteRecord` 即 MAJOR（3.0.0 在 rc 线，先 bump rc 再动）。存量迁移回填规则+一条验证脚本证明零人工落位。
5. **性质测试**：每条不变式落成 vitest 可执行性质——过期闪念只能 promote/显式 trash 且 trash 前置可执行；permanent 卡 delete_note 必拒；archive 前置未蒸馏入链检查。
6. **仪表**：量飞轮，不只量清理——**组合率**（链接密度随卡片数增长斜率）、**激发率**（谜面→新卡转化）、处置率（过期闪念 promote+trash 占比）、待加工队列趋势。落成工具或面板数字。
7. **真机验收**：3080 稳定节点，逐项写"看什么/通过标准"；含盲测——新建盒子跑会话，AI 须主动提出过期闪念的炼/扔提议。

## 4. 裁决记录（2026-11-02，代码前定案）

1. **三 vs 四 → 三类。** 文献笔记的差异化特征是出处元数据（书目信息），不是生命周期状态——它与闪念同寿同终局（加工→永久或弃）。本插件无书目域；加出处层 = 新职责域（更大，不是更深）。阅读进料折叠进 capture_note 的描述纪律。判据（任务书 §2.1 原文）"飞轮需不需要独立的阅读进料状态"——不需要：需要的是纪律不是状态。
2. **扔的语义 → trash 是显式动作，无 TTL、无定时器。** 过期只改变可见性（进料队列置顶），绝不自动删行。与 `STALE_DAYS=7` 共存且语义分开：闪念进料窗 2 天（用户定义），迷失卡窗 7 天（卢曼 C4，只算永久/项目卡）。**对任务书 §2.5 的显式偏离**："permanent 卡 delete_note 必拒"不采纳——机制侧真正的保护是 card-referenced 守卫（已在、已测）；必拒会造死端（重复卡/错卡永远无法清理），违反本仓减法纪律；Ahrens"永不扔"是盒的价值论，不是 API 语义。
3. **双入口 → 两个工具，不是一个工具加 kind 参数。** capture_note（闪念：免标题、可悬链）与 write_note（永久：一卡一想法+解析拒绝）是两套纪律，单一 schema 的描述教不清晰——D8"纪律活在工具描述里"哲学的延伸。promote_note / archive_note 是显式转移动词。**作用域**：capture_note 进全局面（随手捕获是闪念的存在理由）；promote/archive 页面作用域（加工需要卡片上下文，与 rewrite/delete 同级）。
4. **schema → 显式 kind 列，正面推翻 rc.1 设计 §3.1 对 type 的否决。** 当时理由"能从 body 派生"对 tags/outbound 成立，对 kind **不成立**：创建时刻的闪念/永久区分（同一张无入链新卡，两种身份不可判）与项目锚（外部实体）都非正文可派生；终局动作的前置检查（archive 的蒸馏证据）需要显式状态。`kind: 'fleeting'|'permanent'|'project'`，默认 permanent——v1 存量行经 zod default 零迁移读作 permanent（全部存量卡本就是按永久纪律写的，落位正确可证）；存储域 version 保持 1。NoteView/NoteSummary 加 kind：rc 线上的破坏性输出扩展。
5. **项目锚 → task-workbench taskId 弱锚。** 取证实据：`TaskItem.id` 真实存在（`plugins/task-workbench/src/types.ts:24`）。anchor 仅格式校验（非空字符串），零硬依赖（不 inject task-workbench）；语义由工具描述教给模型。不砍项目类的理由：锚真实存在且用户显式点名项目笔记。
6. **图可见性 → 闪念对链接图不可见。** 不进 `links` 缓存、不可被 `[[…]]` 解析为目标、不参与枢纽/反链/谜面/迷失区。只有化合产物入网——这是飞轮的结构表达，也使 I3（存储态永无悬挂）在闪念可悬链的前提下依然成立。**不变式 I2 随之修订**：标题唯一性收敛为"链接目标卡（非闪念）内唯一"——闪念不是地址，重复不产生歧义；这让进料口免于标题撞车摩擦。永久/项目卡之间的唯一性与改名/删除语义原样。
7. **仪表 → `ledger` 账表 + `box_stats` 工具。** append-only 动作账（captured/promoted/trashed/archived/riddle_closed），盒的动作量是人肉尺度，账表恒小；比率按 7 天窗口算。谜面闭合检测：改写路径新增直链时，若该对此前共享邻居 ≥ `RIDDLE_MIN_SHARED` 且此前无双向直链 → 记 riddle_closed（激发率的机械可测部分；不可测的"谜面被看过但被否"如实不测）。
8. **版本 → `4.0.0-rc.1`（执行期修正）。** 原判 `3.0.0-rc.7`，但执行期间并行列车已把 3.0.0 正式版发进不可变 registry（commit 7f8a0fd）；本次扩张（NoteRecord/NoteView/NoteSummary/NotebookErrorCode/NotebookToolsPort，错误码联合扩张对穷举 switch 是编译破坏——rc.1 设计 D11 的 MAJOR 判据）按版本规范落新 MAJOR 线 `4.0.0-rc.1`，走 -rc.N 先过预发布环境。家族四包同线齐升。

### 取证审计回填（2026-11-03，`docs/notebook-audit-results.cn.md`，证据在案）

9. **转轨缺口（G2）→ 补 reclassify 动词。** 真机终态存在"应属项目却住永久盒"的卡（Sub2API 定价策略草稿），而 promote 只吃 fleeting（lifecycle.ts:114）、archive 只吃 project（:150）、@Remote 面无 reclassify——该卡永远进不了项目生命周期。补 `reclassify`：→project 须带 anchor，→fleeting 禁止；与 promote/archive 同级页面作用域。
10. **残渣清理（G1'）→ title 锚定预筛 + 人审终裁，禁全自动删除。** 取证审计的双评分者实验证明：title∪body 正则会误杀全盒最好的卡（正文"验证发生在输出侧"撞词）；title-only 变体与独立评分者 13/13 一致。清理通道 = title 锚定预筛列出候选 + 人审确认，不允许无人审批的批量删除。仪表补 orphanCount（实测孤岛 5/13，含零再接触的最优卡）；审计漏斗数字（F1=18/F4=3/F5=5；F5/F1=0.28、出链密度 0.5）记为"改造前"基准线。
