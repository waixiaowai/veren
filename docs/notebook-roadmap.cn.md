## 1. M1——盒在别处说话（情境化调用）

**灵感**：卢曼「与卡片盒交流」——盒是随时可对话的第二个我；Ahrens 原则2「没有人从零开始」——每个新会话都应站在盒的肩膀上。这是验收实测的最大痛点：干活时 AI 不会想到查盒。

**概念一句话**：把卡片盒工具面从「仅 notebook 页面」提升为「预设级能力」——该预设的**任意会话**都能咨询与写入盒子，按需轻重两档：

- 轻档（先做）：预设级 skill（复用 person-agent skills isolate 挂载模式），把 `list_notes / read_note / find_cards / write_note` 四件注入预设的每个会话；工具描述写明「想起盒里可能有关的卡就先查」。
- 重档（后议）：首屏注入「盒的一句话状态」（卡数+枢纽 top3）进系统提示——涉及宿主 system-prompt 面，成本高，需单独取证。

**契约要点草案**：owner 仍从活 Agent 解析（不变式不变）；页面挂载与 skill 挂载走同一工具构建器（零双轨）；冲突面=工具在本页与全局同名的注册遮蔽语义——按 registerAppSteps 的遮蔽先例取证后定。

**执行前置**：深链/boot URL 消费者修复不是前置（两件事独立）；需要宿主 skills isolate 的挂载取证。

**执行记录（2026-11-02，rc.4 已上线）**：取证推翻了 skill 方案——task-center 的全局 face 才是既成模式（service 构造器里 `ctx.tools.register`，插件作用域=全局）；注册表文档语义「scoped tools shadow globals」逐字在案，因此全局面直接沿用页面全名（`notebook__list_notes/find_cards/read_note/write_note`），页面会话同名遮蔽，每能力一个名字。`Config.globalTools.enabled` 默认开；rewrite/delete 仍页面独占（L2）。测试 G1-G3（注册序/开关/逆序 dispose+HMR 无碰撞）经记录型注册表断言，41/41 绿。真机裁决（rc.4）：普通会话 find_cards 命中 4 卡+write_note 落盘（92fb102b）；页面会话 read_note（页面不挂载、全局面供给）真调成功返回卡全文——遮蔽与可见性双验证。证据 11/12。

## 2. M2——加工节拍：闪念浮出面（迷失卡片救援）

**灵感**：Ahrens 的三类卡工作流（闪念几天内必须加工，否则烂掉）；卢曼 C4「不相连的笔记会迷失，会被盒遗忘」。「上下文逼你思考」——加工的动作就是把孤卡拉进上下文。

**概念一句话**：列表页首屏增加「待加工区」段——**纯派生、零新字段**：无入链且updatedAt 早于 N 天的卡（迷失卡片），让 AI 在每次重入盒时先看见它们，主动问「这几张要不要炼成永久卡」。

**契约要点草案**：派生规则 = `inbound==0 && updatedAt < now-N天`（N 可先定 7 天常量）；排序按 updatedAt 最早优先；首屏消息如实标注「这些卡还没有任何链接指向它们——按方法该加工了」。**不做**：状态字段/标签（第二事实源红线不动）、自动归档。

**执行记录（2026-11-02，rc.5 已上线）**：`staleView` 派生进 graph.ts（双表查询，最早优先）+ `Remote('stale')` + 端口 `stale` 成员；列表首屏新增「待加工区」段（空态如实）。测试 S1（派生恒等式：老孤儿进队/有入链排除/新卡排除/窗口=0 全进队——注意出链不锚定自己）+ 首屏渲染 2 断言，42/42+19/19 绿。真机裁决：真实生产介质过真实派生 = 恰好浮出 Sub2API playbook（12 天）与 2.0.4 回归（9 天），有入链的 2.0.3 与新鲜 rc1 卡正确排除；UI 截图因自动化点击管线退化（会话切换失效，见深链发现）未能拍到——人肉点开「笔记列表」会话即见，首屏投递机制本身已被当日多份截图证明。

**执行前置**：无；graph/linkCounts 已能派生。

## 3. M3——从盒到文稿（写作面）

**灵感**：Ahrens 原则1「写作是唯一重要的事」、原则2「没有空白页」——卡片盒的终点是文稿；用户早先「写匠 AI Writer」参考正指这一段。卢曼写了 70 本书：盒→结构卡→手稿是方法的收口动作。

**概念一句话**：给定一张结构卡（或一个主题查询），AI 沿链接圈卡、排序，产出一张**草稿卡**（新卡，正文=文稿骨架：每段引用来源卡 `[[标题]]`）——写作起点落回盒内，不引入第二存储。

**契约要点草案**：草稿卡是普通卡（忠实卢曼——手稿也进盒）；不建「文档」实体、不做 markdown 渲染（D10 不动）；`find_cards` + 反链已能给圈卡供料；新工具面（如 `assemble_draft`）是否值得立——先跑通「无新工具、纯对话组合」的用法，缺了再立（YAGNI 复核）。

**执行前置**：M1（别处说话）最好先行——写作发生在工作会话不在盒页；盲读测试宜在 M3 前跑（文稿质量依赖卡片原子性）。

## 4. M4——意外连接（发现面）

**灵感**：Ahrens 原则6「让偶然性扮演角色」；采访金句——笔记的价值在于「surprise」（Bateson：造成差别的差别）。图谱现在只**回答**（谁链我/枢纽是谁），不**出谜**。

**概念一句话**：列表页首屏/枢纽段增加「谜面」——**共享邻居却从未互链**的卡对提示（如「「A」与「B」共享 2 个邻居但从未互链——看看？」），把方法里的「意外连接」工程化为一个派生谜面。

**契约要点草案**：派生自 links 缓存（零新字段）：`共享邻居数 ≥2 且互不链接` 的卡对 top3；措辞如谜不如下结论（谜面语气保持提问式）；点击即选中其中一张（复用 rc.3 的链接点击装配）。

**执行前置**：无重前置；注意谜面算法在 1 万卡时的成本（links 缓存全扫，rc 基准先测）。

## 5. M5——出口：导出为 markdown（逃生门）

**灵感**：Ahrens 原则10「组织发展而非产出」的前提是数据可携带；数字盒的长期主义要求出口。方法兼容格式 = 每卡一个 .md 文件（标题=文件名，`[[标题]]` 链接=相对链接）——与主流工具互通。

**概念一句话**：面板「导出」按钮 → 打包该归属全部卡为 markdown 文件夹（Obsidian/Foam 直接可开）——只出不进，单向逃生门。

**契约要点草案**：文件名=title（唯一性保证无碰撞，URL 编码落地）；导出不经存储域写任何东西；交付走浏览器下载或 deliverUrl。

**执行前置**：低；可随时插入。
