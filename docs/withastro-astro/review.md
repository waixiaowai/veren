### 30.5 Fact Corrections

| 设计中的写法 | 源码事实 | 处理 |
| --- | --- | --- |
| `ContentCollectionMissingLoader` 有明确抛出阶段 | 只有错误定义，未见抛出点；实际抛出 `InvalidContentEntryDataError` | 10 章只作名称引用 |
| 关闭会话后访问会报错 | `session: false` 时 `context.session === undefined` | 12 章按 `undefined` 描述 |
| 静态构建的图片走 `/_image` | 静态构建输出到 `_astro/`；`/_image` 仅开发与按需渲染 | 9、17 章已区分 |
| 缓存提供方总能保留 `CDN-Cache-Control` | 带 `onRequest` 的提供方会剥离这些头 | 12 章与 A-12-05 已按此写 |
| 语言服务器不提供格式化 | 通过 `volar-service-prettier` 提供，需项目自带 prettier | 16 章已按此写 |

| `@astrojs/node` 静态头文件名为 `headers.json` | 实际为 `_headers.json` | 14 章已按此写 |

### 30.8 Conclusion

方案覆盖 15 个模块、7 个接口、5 类主体、48 个错误码、7 个状态主体、13 个页面与 49 个组件；核心域 4 个，占比约 27%，与模块章的核心深化要求一一对应。内容符合 Astro 内容集合契约：frontmatter 只含允许字段，正文无 H1，站内链接为 `/design/...` 路由，图为构建期 SVG。

未完成的实质工作：权限主体模型待维护者确认（H-05）、工具栏界面本地化与四态属拟议（H-06）、真实宿主中的开发界面与适配器行为未复核（30.4）。这些不影响文档作为设计与评审依据，但不能据此宣称系统已通过验收。

### 30.9 Core Business Check

核心域按 [核心业务识别](/design/architecture/#12-core-business-identification) 的三判据裁决，逐域简证如下。

| 域 | 判据一 主链不可缺 | 判据二 失守即失格 | 判据三 砍余仍可用 | 结论 |
| --- | --- | --- | --- | --- |
| Routing | 主链第一步即解析请求归属 | 路由错则页面错、缓存脏 | 只留路由与最简入口仍能给出确定结论 | 核心 |
| Compile | 页面输出必经编译产物 | 编译错则页面缺段 | 只留编译可产出可渲染单元 | 核心 |
| Render | 请求到响应的唯一通道 | 响应错即用户可见故障 | 只留渲染与最简入口可出响应 | 核心 |
| Build | 静态交付必经构建 | 产物错则无法发布 | 只留构建即可静态交付 | 核心 |
| Config | 缺失则无法启动 | 设定错影响全局 | 单独保留无法产出页面 | 外围 |
| Assets | 缺失时仍可输出无图页面 | 影响性能与可访问性 | 单独保留无法成站 | 外围 |
| Content | 无内容仍可写纯组件页 | 影响内容站价值 | 单独保留无法成站 | 外围 |
| Actions | 无动作仍可读页面 | 影响写操作 | 单独保留无法成站 | 外围 |
| Storage | 无会话仍可匿名访问 | 影响登录态 | 单独保留无法成站 | 外围 |
| Server | 无开发服务器仍可构建 | 影响调试效率 | 单独保留无法交付 | 外围 |
| Integrations | 无集成仍可构建 | 影响扩展能力 | 单独保留无法成站 | 外围 |
| Adapters | 静态输出不需要适配器 | 影响部署形态 | 单独保留无法成站 | 外围 |
| Navigation | 关闭过渡仍可导航 | 影响体验 | 单独保留无法成站 | 外围 |
| Tooling | 编辑器可换 | 影响书写效率 | 单独保留无法成站 | 外围 |
| CLI | 可用 API 直接调用 | 影响入口体验 | 单独保留无法成站 | 外围 |

比例核对：核心 4 个，模块总数 15 个，占比约 27%，落在 0.1 到 0.4 的可接受区间。判定存疑的域是 `config`：它在主链上且失守即全局失效，但"砍余仍可用"不成立（无编译与渲染无法产出页面），因此不列入核心，改以"配置非法立即失败"写入 3 章验收。若维护者认为设定即产品边界，可将其升为核心，届时需补铁律决策与恢复策略。
