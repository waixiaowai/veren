# IM 消息队列语义规格（微信路径重构）

> 状态：本文件是 2.1.8 重构的规格基准。实现与本文件冲突时，先改本文件再改代码。
> 英文版：[im-message-queue.md](./im-message-queue.md)。

## 概念

用户只面对「发消息 → 收回复」。会话不再是用户面概念：网关按 conversation 私有持有
会话（懒创建、消费时按需恢复），用户不需要也不能手动绑定。消息路径为队列语义：

```
接收 → 入队（幂等）→ [排队告知（仅当会话已有在途）] → 消费（私有会话）→ 回复 → 终态
```

## 投递语义规格表

每一行都引用本仓库真实发生过的故障作为存在依据。

| 维度 | 决策 | 依据（真实事故/事实） |
| --- | --- | --- |
| 投递保证 | **至少一次**：`consuming` 中崩溃 → 重启重入队再消费；可能产生重复回复（日志可审计），绝不静默 | 重启窗口消息石沉大海（gateway resume 修复前每条必死）——宁可重复，不可无声 |
| 顺序 | 同会话 FIFO（received_at 序），至多一条在途；跨会话并行互不阻塞 | 内存串行链已是现状语义；绑定删除后由队列显式承担 |
| ack 时机 | 会话已有在途/排队消息时，新消息立即回「已收到，正在处理，前方 N 条」；空闲则直接等结果回复，不发冗余 ack | 模型回合实测 30s+；无 ack 的排队在用户感知上就是石沉大海 |
| 重试/死信 | 消费失败自动重试（重新排队），累计 3 次失败置 `dead` 终态并向用户回一条失败告知 | `sendmessage -2`（频控/context 失效）与模型回合超时（replyTimeoutMs=120s）是已知失败源；现状失败只进日志、用户无感知 |
| 幂等 | `message_id` 持久唯一键；重复入队为 no-op | 监控 `seen` 环只覆盖近期且在内存中，重启即失效；iLink 离线消息不保证不重复 |
| 持久化 | 队列表（`messages`）与会话映射表（`conversation_sessions`）持久化在 `im` 存储域，重启恢复消费 | registry 的 `early[]` 内存缓冲重启即失忆——石沉大海的根因之一 |
| 会话归属 | `conversation_id → session_id` 私有映射，懒创建；恢复由 `gateway.ask` 内部处理；不轮换 | bot 重配对后 account 漂移而 `conversation_id` 稳定（retarget 机制已实证）；会话对用户不可见，故无轮换需求 |
| 公平性 | 跨会话天然并行（每会话独立链，无全局队头），单会话内严格串行 | 多个用户共享一个 bot；一个重用户不得阻塞其他人 |

## 删除清单（不留双轨）

- `bindings` 表与 `ImBinding` 契约、link/unbindBinding/settings 的服务与远端面
- 绑定页/未接入列表 UI（替换为「会话」页：按会话展示队列状态）
- `im_link` 模型工具（会话不再需要绑定动作）
- `autoCreateSession` 配置项（会话永远自动私有创建，配置面随之消失）

保留不动：账号授权向导（账号级 QR 授权）、人员目录、采集、账号生命周期（退役/对账）。
`retargetAccount`/`migrateBindings` 随绑定表消亡；账号退役迁移改为迁移会话/消息/地址
（会话映射表只按 conversation_id 键控，天然免迁移）。

## 不变式（属性测试断言）

1. **不丢**：每条入站消息必有终态 `replied`/`failed`（已告知）/`dead`（已告知）；无结局即违规。
2. **不重**：同一 `message_id` 在队列中至多一行；重复入队是 no-op。
3. **有序**：同会话内消费顺序 = received_at 顺序；至多一条 `consuming`。
4. **可路由**：消息回复只经其账号可送的路径发出；死账号上的在-flight 消息在账号退役时迁移。
5. **自愈**：重启后 `consuming` 行全部回到 `queued`；失败行按 attempts 重试直至 dead。

## 验收协议（不由你我裁决）

1. 属性测试：随机交错 [入队、消费、消费中崩溃、重复入队、回复发送失败] 断言上表不变式。
2. 三项硬演练：消费中强杀宿主重启后无静默消息；同 id 双投恰一回复；三连消息按序三回。
3. 脚本终态审计：捕获文件 + `messages` 表联合断言每条 message_id 有终态。
4. UI 由浏览器自动化断言新形态（会话页存在、绑定页消失）。
5. 连续多天、多次重启，零石沉大海。
