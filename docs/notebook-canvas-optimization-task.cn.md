## §1 四问

### 1. 顶级专业会多做什么（没被要求但该做的）
- **启发式评估**：按 Nielsen 十条 + 画布品类启发式（Miro/Heptabase/Obsidian-canvas 的公认基线）对整面板过一遍，每条打 0–4 严重度——「不合理」不再靠驭驾式裁定，而是有分级账本。
- **任务计时基线**：三条核心任务（找枢纽卡 / 加工一条进料 / 讲出两卡关系）的点击数与耗时先量一次，优化后再量——「更合理」必须以任务面数字裁决，不以观感。
- **空态与首跑体验设计**：首开面板的 7 秒决定生死（归属、空态、引导），专业产品把它当独立规格写。
- **可读性阶梯先行**：先定「什么缩放下什么信息可见」的 LOD 表，再谈 fit 行为。

## §2 裁定（O 系列）

- **O1（P0）归属选举重写**：`chooseOwner` 改为「有卡的盒优先（按卡数×最近活跃降序）→ 声明空盒殿后」；选中结果记 localStorage（每浏览器记忆 lastOwner），显式切换覆盖之。选举落纯函数 `electOwner(owners, lastOwner)` + 单测。
- **O2（P0）新建流程接通**：画布模式点「新建笔记」→ 自动切列表模式并进入编辑（列表=创作面，画布=关系面——与「画布无编辑」裁定自洽）；保存后切回画布可见新节点。状态机：idle → authoring(list) → saved(canvas)。
- **O3（P1）画布空态**：nodes=0 时画布中央渲染空态卡（复用列表的 noNotes 文案 + 「切列表新建」引导）；纯展示。
- **O4（P1）可读性优先的默认缩放**：打开/切归属不再 fit，默认 zoom=0.85、居中于枢纽环质心；「适配」保留为显式按钮。缩放策略落纯函数 `initialView(layout)` + 单测；LOD 表（0.85 全细节）写进交互规格。
- **O5（P1）归属记忆**：同 O1 的 localStorage 持久化（lastOwner）， elections 只在无记忆且多盒时生效。
- **O6（P2）曲线边**：直边改二次贝塞尔（按环向偏移控制点），命中线同步；纯渲染改动+真机截图裁决。
- **O7（P2）dock 收纳**：过期数 ≤3 时 dock 保持现形态；>3 收成一行计数+展开钮。视觉裁决截图。
- **边界**：不动宿主详情页零工具（defect D，page-registry 泳道）、不做画布内编辑（用户已裁定）、不拆 canvas.tsx 文件（拆分诅咒已立案）。
