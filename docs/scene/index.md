## Summary

把「场景」做成**房间**：同一个智能体（预设=这个人），在办公室、家里、车上、咖啡厅各有自己的一间房——每间房绑定一个专属的长活会话。进门 = 恢复那间房的会话（工具、技能、对话上下文原样都在）；出门 = 那间房的会话在后台继续干自己的活。记忆是**五层阶梯**：会话里的临时记忆、项目的工作记忆、房间的场景记忆、人的个人记忆、无主体的世界记忆——重复的知识被蒸馏器逐层提炼上行，读取时全阶梯可见，兄弟房间的原始记忆结构性互不可见（办公室的记忆永远不会出现在家庭的对话里）。切换场景就是切换房间，**任何一间的缓存、声明、会话都不因切换而变化**。

## Problem

目标用户是深度使用智能体的个人与团队：同一个助手既要在工作时段写代码查资料，又要在生活时段记家事陪聊天，还要在通勤、阅读这些碎片场合里各有一套合适的本领。今天的现实是三类别扭：能力挂载是死的（装上就常驻，换场合靠手动开关插件）；挂载逻辑各处手写（不同页面各造一套互斥规则）；记忆不分场合（上班时召回带娃笔记，陪孩子时召回代码片段）。

方案演进中否决过一条路线：在同一个会话内中途换装（换工具声明、换提示词）。它有三座绕不开的大山——工具声明位于模型缓存前缀的最前面，中途改声明必然击穿缓存；「真不可见」与「缓存稳定」不可兼得；切换碎片永久累积在历史里。v3 改为**房间模型**：场景×预设的组合绑定各自的会话，切换即换会话——上述三座大山连同其全部补救机制（缓存分级、声明策略、搭压缩便车）整体消失。

## Core Architecture

整套机制是「一个人、五件家什」。**登记处**收下每个房间的门牌说明：这个组合（场景×预设）带哪些工具、激活哪些技能，声明随会话而生、永不中途改。**判定器**回答「现在该进哪间房」：人随时显式进入，系统也可以按上下文自动建议——默认只建议不自动进门（换房权在人），判定须过迟滞门防抖。**绑定器**管房间的钥匙：每个组合一条绑定行，指向它的专属会话；首次进门以该组合的预装配好会话，之后再进即原样恢复；出门时若有在途回合，会话在后台无人值守继续。**场景记忆**是五层阶梯——会话临时、工作区工作、房间场景、预设个人、无主体世界；记忆只有一套工具：recall 读全阶梯、write 只写会话临时层，其余层的记忆全部来自晋升；蒸馏器每日回顾当天会话，把重复的知识逐层提炼上行（只上行、跨主体晋升须过治理门），显式晋升是 L0 源的人工覆盖通道。**指示面**是门牌：现在在哪间房、系统建议去哪间、一键进入。

三条铁律：**换房权在人**——模型与自动判定都不能擅自改变人所处的房间；**会话面冻结**——每个会话的能力声明自创建起不变，切换不触碰任何会话的前缀；**记忆阶梯各守其界**——兄弟房间零泄漏（结构性隔离），晋升只上行且跨主体必须过治理门，工作区组织元数据仍不可见。
