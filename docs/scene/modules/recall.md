## 1. Responsibility

场景记忆回答「谁记得什么、记忆如何上行」。它定义记忆的五层阶梯与层间的晋升管道，守住两条界：兄弟房间零泄漏（结构隔离），跨主体晋升必须过治理门。它与相邻模块的分界：绑定器把会话指给房间，场景记忆定义记忆归谁、谁能读、怎么上行；判定器与它互不相干。

## 2. The Memory Ladder

五层，主体从具体到通用：

| 层 | 主体 | 是什么 | 例 |
| --- | --- | --- | --- |
| L0 临时记忆 | session | 会话内的情节与未沉淀事实 | 本轮对话内容、刚说的约定 |
| L1 工作记忆 | workspace | 项目级沉淀：这个项目的决定、约定、坑 | 「本项目用 pnpm，禁 npm」 |
| L2 场景记忆 | combo（场景×预设） | 房间沉淀：这个场合的长期事实 | 办公室的代码偏好、家里的作息 |
| L3 个人记忆 | preset | 人的长期事实与偏好 | 名字、语言、跨场合习惯 |
| L4 世界记忆 | null（无主体） | 跨人成立的通用知识 | 工具行为通则、全局约定 |

可见性总规则：**兄弟房间互不可见（L2 结构隔离），除此之外读取面 = 全阶梯**。模型在某间房能看见：本会话情节（L0）+ 本项目工作记忆（L1）+ 本房间场景记忆（L2）+ 个人记忆（L3）+ 世界记忆（L4）。敢全开的原因：每一层都只存放提炼后的条目，体积小；原始情节永远只留在 L0 与所属房间，不随阶梯走。

## 3. The Promotion Ladder

晋升判据只有一条：**重复**。同一条知识在层内反复出现，就由蒸馏器提炼成上一层的条目：

| 晋升 | 判据 | 去向 |
| --- | --- | --- |
| L0 → L1 | 会话内重复出现的知识 | 该会话所属工作区的工作记忆 |
| L1 → L2 | 相同场景下重复出现的工作记忆 | 该房间的场景记忆 |
| L2 → L3 | 相同预设下重复出现的场景记忆 | 个人记忆 |
| L3 → L4 | 跨预设重复出现的记忆 | 世界记忆 |

执行机制：

- **蒸馏器**是异步维护任务（回合间隙或会话收尾时运行，模型参与「重复」的判断），产出晋升候选条目写入目标层；阈值（出现 N 次 / 跨 M 个单元）是蒸馏器配置，不是硬编码。
- **只上行不下行**：晋升只把提炼条目写向上一层，任何高层条目不写回低层；原始情节不随晋升移动，留在原处。
- **显式晋升是人工覆盖通道**：用户（或带确认的模型动作）可跳过重复判据直接晋升一条记忆——保留 v3 的「显式提升」语义作为管道旁路。
- **治理门（铁律）**：L3 → L4 是唯一跨主体的晋升，默认禁止自动执行，必须经策展（人工审核或显式批量确认）；一个人的习惯不应自动变成「世界真理」。

### 3.1 The Daily Distillation Job

蒸馏器的执行通道定稿为**每日定时批处理**——回顾当天全部历史会话，触发 L0→L4 的整理晋升：

- **触发**：经宿主定时任务设施注册，每日触发一次（默认次日 00:30，配置可改）；错过触发点则顺延至下次触发，不追补多次。
- **窗口与水位**：处理 `[上次成功完成, 本次触发)` 的会话活动窗口；每层维护独立水位，同一窗口重跑幂等，不重复晋升。
- **范围**：窗口内有活动的全部历史会话，按各自作用域键归组——会话内蒸馏归其工作区（L0→L1），工作记忆按房间归集（L1→L2），场景记忆按预设归集（L2→L3）；读取走既有会话查询设施，不翻原始账本。
- **隔夜冷却**：每晚每级只处理各自窗口的输入；本轮新晋升的条目次日才参与上一级蒸馏——防止一条事实一夜连跳四层。
- **治理队列**：L3→L4 候选只进审核队列等待策展，不出现在自动晋升结果里。
- **成本上限**：蒸馏的模型调用经记账模块计价，单次运行有可配置预算；超出部分顺延到下次触发。
- **失败隔离**：按作用域分组独立执行，单组失败不影响其余组；整体失败下次触发整体重试（水位保证幂等）。
- **执行位**：宿主侧无人值守运行，不依赖任何用户在线。

## 4. The Unified Memory Tool Face

所有层级的记忆共用**一套工具**，只有两个操作：

| 工具 | 语义 | 能力边界 |
| --- | --- | --- |
| `memory_recall(query)` | 读取：按可见性规则返回全阶梯（L0–L4 各自作用域内）的匹配条目 | 只读；兄弟房间原始记忆不在可见面内 |
| `memory_write(content)` | 写入：只能落 L0（本会话临时记忆） | **接口没有目标层参数**——向 L1–L4 直接写入在结构上无表达形式 |

由此推出本模块最强的两条不变量：

1. **单一写入口**：L1–L4 的记忆**全部**来自 L0 的晋升，不存在任何第二条写入路径——不是「检查后拒绝」，而是「接口形状使高层写入不可表达」。
2. **显式晋升重定义**：人工覆盖通道（SVC-8）的源头必须是 L0 条目——它不直接写上层，而是对指定 L0 条目立即执行晋升管道（跳过重复判据；L3→L4 仍须治理门）。v3 的「显式提升直接写上层」路径作废。

工具随会话预装配挂载（每间房都有，无需场景声明）；模型可自主调用 recall 与 write，但不运行蒸馏器——晋升仍归管道与治理门。

## 5. Workspace Principle Revision

工作记忆层落在工作区上，是对宿主工作区原则的一次显式修订：**工作区的组织元数据（分组、排序、置顶）仍对模型不可见；新增的项目级工作记忆按需可召回**。「工作区零 token」让位于「项目知识按需召回」——这与业界项目记忆（如仓库级指令文件）形态一致，修订记录见[校验与假设](../review/)。

## 6. Boundary

明确不做的事：不建跨房间读原始记忆的通道（兄弟房间的 L2 互不可见，房间记忆进上层只能经蒸馏提炼）；不让蒸馏器自动执行 L3→L4；蒸馏器本轮仍为方向级设计（执行通道已定稿为每日批处理，蒸馏器本体随宿主任务设施实现，见[校验与假设](../review/)）；身份不是记忆——人格由预设声明承担，任何记忆层都不承载身份语义。

## 7. Acceptance

1. **跨房间零泄漏（核心，隐私）**：办公房间的 L0/L2（含压缩摘要）在家庭房间的模型可见输入中审计为零；能跨房间出现的只有 L3/L4 的提炼条目。
2. **读取面 = 全阶梯**：房间内模型可见记忆恰好为 L0–L4 五层条目集合，不多（无兄弟房间原始记忆）不少（各层齐备）。
3. **晋升只上行**：任一晋升动作后，低层条目原样保留；不存在高层条目写回低层的路径。
4. **治理门拦截**：未过策展的 L3→L4 自动晋升被拒绝；显式晋升不经过重复判据但留下提升记录。
5. **蒸馏可重放**：同一蒸馏器对同一输入的运行结果可从账本与候选条目重建（重建性要求与宿主账本不变量同法）。
6. **每日任务幂等**：同一窗口重跑每日整理任务，晋升结果与首跑一致（水位与隔夜冷却保证），无重复条目。
7. **治理队列承接**：L3→L4 候选全部进入审核队列，自动晋升结果中不出现任何世界记忆条目。
8. **write 仅落 L0**：`memory_write` 的任意内容只出现在本会话临时记忆；各上层存储中不存在任何绕过晋升管道的直接写入痕迹（接口无目标层参数，结构上不可能）。
