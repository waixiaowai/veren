### 30.2 Core Business Verification

核心业务流：人类在房间发言 → 某个智能体被唤醒 → 在同一房间给出有用回应或明确保持安静。沿链候选 9 个域，裁决如下。

| 域 | ① 主链不可缺 | ② 失守即失格 | ③ 砍余仍可用 | 结论 |
| --- | --- | --- | --- | --- |
| Conversation | 是：事实无处安放 | 是：事实权威 | 是：仅会话与入口仍是一个可用聊天室 | 核心 |
| Turn | 是：没有它就没有行动 | — | 是：仅回合与入口仍是一个会回应的同事 | 核心 |
| Coordination | 是：决定谁动 | 是：失效即退化为刷屏机器人 | — | 核心 |
| Agent | 是：身份与记忆进入每次思考 | — | 是：仅身份与记忆仍是一个有连续性的同事 | 核心 |
| Host | 是：没有执行位置就没有回合 | 是：凭据泄漏或越权执行 | — | 核心 |
| Workspace | 是：每次读取都要租户范围 | 是：越界即信任崩塌 | — | 核心 |
| Realtime | 是：回应要送达 | 否：延迟不等于错误 | 是：拉取即可恢复 | 外围 |
| Identity | 是：请求先有主体 | 判定存疑 | 是：单租户下仍可用 | 外围（存疑） |
| Billing | 否：不产生用户可感知产出 | 否 | 否 | 外围 |

比例：核心 6 个 ÷ 模块 16 个 = 37.5%，位于建议区间 0.1–0.4 的上沿。理由是产品的差异化同时落在"谁在说"与"谁被允许说、在哪台机器上说"两端，删去任一端都不再是同一产品。判定存疑项：Identity 与 Workspace 同属准入面，最终只把拥有租户数据与删除顺序的 Workspace 计入核心，把凭据机制视为可替换实现；若评审认为准入不可拆分，核心比例将升至 43.8%，超出区间，需要重新划分模块粒度。此项记入待确认。

### 30.4 Not Verified

| 项 | 原因 | 影响 |
| --- | --- | --- |
| 被描述系统的真实运行行为 | 方案基于源码与仓库文档，未启动数据库、缓存、宿主与模型 | 端到端验收条款是可执行判据，不是本次已通过的结果 |
| 真实模型、邮件与推送网络 | 需要外部凭据与真实域名 | 相关失败分支按代码语义描述，未实测 |
| 桌面与移动运行时观感 | 未构建桌面安装包与原生壳 | 窗口装饰、安全区、键盘行为以代码与文档为准 |
| 站点在目标浏览器中的最终呈现 | 只在无头 Chromium 中验证，未做 Safari、Firefox 与真机人工走查 | 字体、滚动与图片解码的跨浏览器差异待确认 |
| 无障碍自动化审计 | 未运行 axe 等工具 | 对比度、可访问名称、焦点顺序仅按规范设计 |
| 容量与性能指标 | 仓库未给出容量目标 | 方案只保留代码中的既有上限，不虚构指标 |

### 30.5 Known Gaps Between Design and Current Implementation

| 主题 | 现状（0.18.9） | 方案要求 | 影响 |
| --- | --- | --- | --- |
| 错误标识 | 只有文案，无稳定码 | 稳定码 + 机器可读字段 | 排障与客户端分支 |
| 工作区选择 | 缺头时静默回退 | 显式要求选择 | 误写其他租户的风险 |
| 页面状态 | 导航状态在内存，无路由 | 关键状态进 URL，刷新可恢复 | 深链与分享 |
| 焦点管理 | 无焦点陷阱，少数浮层声明模态 | 高频浮层统一焦点陷阱 | 键盘与读屏体验 |
| 接口限流 | 无 HTTP 限流中间件 | 至少对写接口与运行时接口限流 | 滥用与成本 |
| 桌面安全头 | 无内容安全策略与导航拦截 | 增加两者 | 渲染进程被注入的风险 |
| 移动交付 | 无移动 CI，安卓版本号固定 | 纳入构建与版本管理 | 发布一致性 |
| 邮件保留 | 正文无保留期 | 明确保留与清理策略 | 合规与容量 |
| 看板约束 | 无 WIP 上限与顺序校验 | 明确是否引入 | 并发移动的语义 |
| 日程语义 | 全 UTC，无日历邀请 | 明确时区与邀请能力 | 跨时区团队 |
| 推送偏好 | 无静默时段 | 明确是否引入 | 打扰控制 |
| 多副本定时任务 | 空闲调度器无锁 | 单副本或加锁 | 重复唤醒与成本 |

### 30.7 Residual Risks

- **文档与实现的时间差**：方案以 `cumora` 0.18.9（提交 `fd3d6c5`）为基线，实现演进后需重跑本章核对。
- **判定存疑项**：Identity 是否应计入核心域，直接影响核心比例是否越界，需评审确认。
- **不可测部分**：模型质量、网络时延、商店审核等外部条件不在本方案控制范围内，验收条款只约束系统侧行为。
