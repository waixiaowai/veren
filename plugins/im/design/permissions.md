## 19. Permissions

本章回答"谁能在哪个边界内做什么"。上半部分定义主体与角色的判定表，下半部分说明隔离如何落到查询、切换工作区时哪些状态必须作废，以及智能体与设备这两种非人类凭据的权威从哪来、到哪去。接口面的凭据形态见 [服务端接口](./api/)，租户本身的创建与删除顺序见 [工作区](./modules/workspace/)。

### 19.1 Subjects

系统里有六类主体。它们的共同点是都能被还原成"某个东西在工作区的某个位置上行动"；区别在于凭据形态、能否切换，以及默认值从哪来。

| 主体 | 定义 | 数据归属字段 | 可否切换 | 默认如何确定 |
| --- | --- | --- | --- | --- |
| 用户账号 | 一个人跨工作区的唯一身份，邮箱唯一，可被停用或软删 | 账号本身不属租户；写入经成员关系落到具体工作区 | 不切换，一个账号可同属多个工作区 | 由会话令牌解析，无法由请求指定 |
| 工作区 | 数据边界单位，前端称 workspace，实体名是公司 | 业务行普遍带 `company_id`；参与者主键为标识加租户的复合键 | 可切换，由请求头显式指定 | 缺省回退最早加入的工作区 |
| 智能体 | 与人类同列名册的行动者，有独立人格、记忆、邮箱与宿主 | 归属租户；消息作者指向参与者标识 | 不可切换，一次请求只能以一个智能体行动 | 由运行时令牌的主体声明决定 |
| 计算机 | 设备凭据，代表一个执行位置 | 归属租户；设备令牌只存哈希 | 不可切换，一台设备只属于一个工作区 | 由设备令牌解析 |
| 外部邮件发件人 | 未注册的通信方，只能经签名邮件进入 | 归属由收件地址映射到某个智能体的工作区 | 不适用 | 由入站邮件的收件地址决定 |
| 平台管理员 | 跨租户的运营身份，不是工作区角色 | 无租户归属，操作写审计事件 | 不切换，同一账号可兼具两种能力 | 由账号上的管理员标记决定 |

主体解析是每个请求的第一步，三条通道互不重叠：

```ts
abstract class SubjectResolver {
  // 人类：会话令牌换用户；租户取自请求头，缺省回退最早加入的工作区
  abstract resolveHuman(token: string, companyHeader: string | null): Promise<HumanSubject>
  // 运行时：令牌换智能体、计算机与放置标识；租户只来自声明，不读请求头
  abstract resolveAgent(bearer: string): Promise<AgentSubject>
  // 设备：设备令牌换计算机；租户来自计算机行
  abstract resolveDevice(bearer: string): Promise<DeviceSubject>
}
```

主体与数据归属之间还有一条容易被忽略的细节：参与者表的主键是标识加租户的复合键，同一个标识可以在多个租户里各自存在。因此"某条消息的作者"必须与"它属于哪个租户"一起读，单看作者标识会跨越租户把两个不同的行动者认成同一个。名册行上的成员数组只是列表投影，任何权限判定都以成员关系表为准，投影过期不会放大权限。

切换工作区是显式动作：界面选择器改写请求头里的租户标识，随后的每个请求都带着它；服务端不从会话、缓存或上一次请求推断租户。默认主体有一个已知风险，必须在本章写清：**缺少租户头时系统会静默回退到最早加入的工作区**。这条回退让漏传头的写请求对着另一个工作区成功执行而不报错，用户看到"保存成功"却发现数据不在当前工作区；多工作区账号越多，命中概率越高。方案要求写操作必须显式携带租户标识，缺失返回 `400 WORKSPACE_CONTEXT_REQUIRED`，读操作可保留回退但响应须带上实际解析到的租户。这是行为变更，落地前标注待确认。

### 19.2 Role Matrix

角色只有三个：owner、admin、member，存在成员关系行上，列默认值为 member。判定只允许三种取值：允许、拒绝、条件；条件用短码表示，逐条列在矩阵之后。带条件的允许在表中仍记为允许，条件列给出前提，前提不满足时按拒绝处理。

| 资源 | 操作 | owner | admin | member | 条件 |
| --- | --- | --- | --- | --- | --- |
| 工作区 | 删除 | 允许 | 拒绝 | 拒绝 | C1 C2 |
| 工作区 | 改成员角色 | 允许 | 拒绝 | 拒绝 | C3 |
| 工作区 | 读成员名册 | 允许 | 允许 | 拒绝 | 角色取真实成员关系，不取投影 |
| 邀请 | 发成员邀请 | 允许 | 允许 | 拒绝 | C4 |
| 邀请 | 发管理员邀请 | 允许 | 拒绝 | 拒绝 | C4 |
| 邀请 | 撤销邀请 | 允许 | 允许 | 拒绝 | 无，幂等 |
| 成员 | 移除 member | 允许 | 允许 | 拒绝 | C5 |
| 成员 | 移除 admin | 允许 | 拒绝 | 拒绝 | C5 C6 |
| 成员 | 移除 owner | 拒绝 | 拒绝 | 拒绝 | 见 19.3，走专用退出流程 |
| 配对码 | 轮换公司配对码 | 允许 | 拒绝 | 拒绝 | 既有设备不受影响 |
| 配对码 | 铸单机重连码 | 允许 | 允许 | 拒绝 | 仅对该计算机有效 |
| 计算机 | 撤销设备 | 允许 | 允许 | 拒绝 | 连带运行时令牌失效 |
| 旁听 | 读智能体私聊 | 允许 | 拒绝 | 拒绝 | 租户已知，返回角色错误而非不存在 |
| 智能体 | 创建 | 允许 | 允许 | 拒绝 | C4 |
| 智能体 | 迁移到计算机 | 允许 | 允许 | 拒绝 | C7 |
| 智能体 | 停用与复职 | 允许 | 允许 | 拒绝 | 保留历史消息 |
| 看板 | 建、改、删、移卡 | 允许 | 允许 | 允许 | C8 |
| 日程 | 建、改、删、立即派发 | 允许 | 允许 | 允许 | C8 |
| 文档 | 编辑 | 允许 | 允许 | 允许 | 无 |
| 文档 | 删除他人文档 | 允许 | 允许 | 拒绝 | member 只能删自己创建的 |
| 邮件 | 发送与回复 | 允许 | 允许 | 允许 | C9 |
| 上传 | 直传与落存储 | 允许 | 允许 | 允许 | 需租户成员 |

条件定义：

| 短码 | 条件 |
| --- | --- |
| C1 | 请求体确认字段与工作区名逐字一致，否则 `400` |
| C2 | 调用者还属于另一个工作区，否则 `409 you cannot delete your only workspace` |
| C3 | 目标不是自己且目标角色不是 owner；不能降级自己 |
| C4 | 未超当前档位的人数或智能体上限，否则 `403` 并给出档位与上限 |
| C5 | 不能移除自己；移除走专用退出流程 |
| C6 | admin 只能移除普通成员，不能移除同为 admin 的账号 |
| C7 | 免费档不得指向托管宿主，否则 `400` |
| C8 | 租户与资源可见性折进同一条语句，不命中即 `404` |
| C9 | 调用者是该会话成员，否则 `404` |

矩阵里有两处容易读错，需要单独强调。第一，**角色面与资源面的拒绝形态不同**：角色不足发生在租户已确认之后，返回 `403` 并说明需要什么角色；资源不存在或不属于该租户返回 `404`，且不区分"不存在"与"无权"。第二，**admin 是运维角色而非次级所有者**：它能做日常写入，但不能改变权力结构（改角色、删工作区、邀管理员、旁听），这条边界一旦松动，一次误操作就能把工作区交出去。

判定按固定顺序执行，顺序本身也是契约：先解析主体，再确认租户成员关系，再检查资源是否存在且属于该租户，最后才检查角色。把角色检查提前到资源判定之前，会让攻击者通过"需要什么角色"的提示探测资源是否存在；把资源判定提前到租户成员检查之前，则会让非成员用同一套 404 掩盖租户边界。两条顺序都不能交换，且每一步失败都不写审计以外的任何数据。

### 19.3 Data Isolation

隔离不靠调用方自觉，而靠查询本身带上边界。所有业务查询默认附加租户谓词，判定与读取在同一条语句内完成，禁止"先查出来再判断能不能看"。

- **租户谓词入查询。** 列表、详情、更新、删除都以租户标识加主键定位；成员资格用连接或存在子查询表达，不用两次往返。
- **越权统一 404。** 会话、消息、看板、卡片、日程、文档、邮件在跨租户或非成员时返回同一句"不存在"，响应体不含角色、所有者或资源类型提示。
- **跨租户聚合不出现。** 搜索、名册、统计、看板快照只在当前租户内聚合；平台管理员的跨租户视图只出现在后台面，且只回计数、花费与账号状态，不回消息正文与文件内容。
- **默认租户不得被隐式继承。** 长连、推送、后台任务都带着建立时解析出的租户；任务重启后重新解析，不沿用进程内缓存的工作区。
- **权力结构变更留痕。** 角色变更、成员移除、设备撤销、配对码轮换都写审计事件，含操作者、目标与结果；审计只追加，不提供修改与删除入口。
- **运营面默认只读。** 后台的跨租户能力限于计数、花费、账号状态与平台开关，不提供读取消息正文、文件内容与文档正文的入口；需要排障时以工单加临时授权的方式另开通道，并同样留痕。

切换工作区时，旧租户的一切派生状态必须整体作废，而不是"再取一次"：

| 状态 | 切换后的行为 |
| --- | --- |
| 消息与列表缓存 | 全部丢弃，按新租户重取，不允许先渲染旧数据再替换 |
| 分页游标 | 序号游标与偏移量一律重置；旧游标可能在新租户命中同号消息，必须禁止复用 |
| 长连订阅 | 退订旧租户全部房间，重新建连并重订；旧连接上的迟到帧按租户标记丢弃 |
| 未读与已读 | 以新租户为准重取，不复用本地累加值，也不回写旧租户 |
| 乐观更新队列 | 清空；未确认的临时消息不得带入新租户，避免"发到别人的工作区" |
| 旁听与开发者工具入口 | 按新租户角色重新判定后决定是否显示，不沿用上一次的可见性 |

实现上用一个单调递增的上下文世代号表达这件事：切换工作区即递增世代号，所有挂在旧世代上的请求、订阅与缓存条目被判定为过期，界面整体重挂载而不是局部刷新。缺少这一步的典型症状是：切换后列表空了一秒又出现上一个工作区的数据，或者在新工作区发消息却落到旧工作区。

### 19.4 Agent and Device Authority

智能体不是一个账号加一个令牌，而是三重身份叠在一起，任何一面缺失都不构成有效行动：

| 身份 | 凭据 | 谁签发 | 何时失效 |
| --- | --- | --- | --- |
| 成员参与者 | 无独立凭据，作为消息作者与名册条目存在 | 建智能体时由服务端铸造 | 停用即离场，历史保留 |
| 运行时身份 | 运行时令牌，声明智能体、租户、计算机、放置标识与固定 scope | 设备就绪后按放置关系签发 | 迁移、撤权、换宿主即失效 |
| 宿主归属 | 计算机行上的归属关系与设备令牌 | 配对时签发 | 撤销设备即失效 |

运行时令牌的声明形状固定，只增不改：

```ts
interface AgentRuntimeClaims {
  sub: string            // 智能体标识
  companyId: string      // 租户，不从请求头读取
  computerId: string     // 计算机
  assignmentId: string   // 放置标识，每次权威迁移都轮换
  scope: 'agent-runner'  // 唯一合法取值
  iat: number
  exp: number
}
```

三条权威规则：

- **声称的身份不算身份。** 请求体里出现的智能体标识、计算机标识、租户标识都不作为授权依据；服务端只用令牌主体，并把它与请求中的资源重新比对。任何"客户端自称"的字段只用于校验不一致，不用于放行。
- **设备令牌可撤销，且撤销立即生效。** 撤销写撤销时间，下一次请求即被拒；心跳只更新在线可见性，不延长令牌寿命。轮换工作区配对码不影响已配对设备，撤销设备才让该机派生的运行时令牌一起失效。
- **移动宿主轮换放置标识。** 把智能体迁到另一台计算机、或同一台计算机上重新分配，都会轮换放置标识，旧令牌在同一请求内失效。系统不维护令牌黑名单，靠每次请求复查租户、计算机与放置标识三者是否仍然一致。
- **免费档不创建托管宿主。** 免费档只有自带宿主；试图把智能体指向托管宿主返回 `400`，播种也延迟到首次配对成功之后，避免为免费工作区预先造出付费执行单元。
- **凭据不出宿主。** 运行时令牌只交给守护进程，引擎子进程拿不到服务端地址与令牌；引擎需要的每次调用都由守护进程代理。这是全局不变量在权限章的具体落点。

配对环节还有一条已知残留风险：工作区级配对码是长期有效的，同一主机名重复配对会复用既有计算机，因此拿到码的人可以在不改动任何已有设备的情况下重新附着到某台计算机，从而继承它的分配关系。方案要求把配对收紧为一次性挑战或强制走单机重连码，但这项收紧尚未落地，标注待确认。

### 19.5 Acceptance

| 编号 | 前置 | 操作 | 可观察结果 |
| --- | --- | --- | --- |
| PM-01 | 用户不是某房间成员 | 读该房间消息并尝试发消息 | 两个请求都返回 `404`，文案与"资源不存在"完全一致，未写入任何行 |
| PM-02 | 同一账号属于两个工作区 | 用 A 工作区标识请求 B 工作区的会话、看板与日程，并执行搜索 | 资源请求均 `404`；搜索结果不含 B 的任何条目、成员或计数 |
| PM-03 | 调用者是 admin | 改成员角色、删工作区、邀请管理员、移除另一名 admin | 四项均 `403` 并说明所需角色；同一 admin 移除普通成员成功 |
| PM-04 | 计算机已配对且智能体在运行 | 撤销该设备后用旧设备令牌与旧运行时令牌调用 | 设备面 `401`，运行时面 `403`；旧令牌不会因重试恢复 |
| PM-05 | 已加载工作区 A 的消息列表与未读 | 切换到工作区 B | 列表整体重挂载，旧游标不再产生结果，未读数按 B 重取，旧租户的迟到帧被丢弃 |
| PM-06 | 调用者是 admin 或 member | 请求旁听全部智能体私聊 | 返回 `403`，响应体不含任何消息内容；owner 请求同一路径正常返回 |
