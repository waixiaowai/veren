## 29. Glossary

本章只做两件事：把业务名词的边界钉死，把技术术语在本方案里的具体含义钉死。两表不混用；正文出现新词时先回到这里定义，不在章节里另造同义词。

### 29.1 Business Terms

| 中文名 | 统一标识 | 解释 | 容易混淆的边界 |
| --- | --- | --- | --- |
| 工作区 | workspace / company | 数据归属与权限判定的单位，成员、会话、看板、日程、文档、邮件都挂在它下面 | 不等于"团队"这种组织概念；一个组织可以有多个工作区 |
| 成员 | member | 属于某个工作区的人类账号 | 与"参与者"不同：参与者是会话里的身份投影，包含智能体 |
| 参与者 | participant | 出现在会话名单里的身份，类型为人类或智能体 | 参与者标识在同一工作区内唯一，跨工作区可重名 |
| 智能体 | agent | 以参与者身份出现、由模型驱动的成员 | 不等于"机器人账号"：它有宿主、引擎、记忆与人格 |
| 人格 | persona | 智能体的稳定身份：名称、角色、风格、系统提示词、身份文件 | 不等于"提示词模板"；人格是持久事实 |
| 记忆 | memory | 智能体跨回合保留的事实，按全局与项目分层 | 不等于对话历史；历史是回合输入，记忆是长期资产 |
| 技能 | skill | 以目录形式安装的能力包，含清单与可选脚本 | 不等于工具；工具是运行时可调用的动作 |
| 回合 | turn | 一次唤醒引发的完整思考与行动，有明确终态 | 不等于一次模型调用；一个回合可以有多跳 |
| 唤醒 | wake | 请求某个智能体开始一次回合的信号 | 不等于"通知"；通知是给人看的 |
| 廉价判断 | triage | 在唤醒前用小模型判断内容是否值得介入 | 不等于路由；路由决定"谁"，判断决定"要不要" |
| 新鲜度闸门 | freshness gate | 写入前检查世界是否已过期，过期则拒绝并回传新事实 | 不等于乐观锁；它拒绝的是"过时的表达"，不是版本冲突 |
| 让位 | hold | 被闸门拒绝后选择不发言或改写后再发言 | 不等于失败；让位是正常结果 |
| 认领 | claim | 对一项工作（房间、卡片、重活）声明占用 | 不等于锁；认领有租约且可过期 |
| 选举 | election | 在多个候选智能体中选出一位代表回应 | 不等于负载均衡；它只解决"一个房间只需要一个声音" |
| 宿主 | computer | 承载智能体思考的机器，类型为平台托管、用户设备或自建服务器 | 不等于"服务器"；同一台机器可以承载多个智能体 |
| 引擎 | engine | 在宿主上实际驱动模型的运行时 | 不等于模型；一个引擎可以配置不同模型 |
| 配对码 | pairing code | 把一个宿主接入工作区的长期凭据 | 不等于设备令牌；配对码可轮换而不影响已配对设备 |
| 设备令牌 | device token | 单台宿主持有的可撤销凭据 | 不等于用户会话令牌；它只能换运行时令牌 |
| 运行时令牌 | runtime token | 宿主为某个智能体换取的行动凭据，绑定归属关系 | 不等于用户令牌；它只对指定智能体有效 |
| 托管执行 | managed | 由平台提供算力与模型的执行方式 | 与"自带智能体"相对，不表示"云端专属功能" |
| 自带智能体 | BYOA | 用户在自己的机器上用本地引擎驱动智能体 | 不等于"本地模型"；引擎可以连远程模型 |
| 共享工作面 | work surface | 看板、日程、文档、邮件这四个非对话产物 | 不等于"模块"；它们是产品概念，底层由四个模块实现 |
| 看板 | board | 由列与卡片组成的任务视图 | 列只是位置与语义，不承诺工作流引擎 |
| 卡片 | card | 看板上可认领、可指派、可评论的工作单元 | 不等于会话消息；卡片变化会产生提及与唤醒 |
| 日程 | schedule / calendar | 共享的时间视图，支持重复与提醒 | 不等于日历协议；当前不生成标准日历邀请 |
| 派发 | dispatch | 到点把日程变成一条面向智能体的系统消息 | 不等于提醒；提醒面向人，派发面向智能体 |
| 文档 | document | 人类与智能体共同编辑的长文本，带快照与增量 | 不等于消息里的富文本 |
| 增量与快照 | update / snapshot | 文档的追加变更与定期合并结果 | 增量不是版本号；快照不是备份 |
| 邮件线程 | email thread | 一个会话对应一个外部邮件线程 | 不等于"邮件客户端"；它把邮件纳入统一消息流 |
| 外部发件人 | external sender | 发件域未对齐或信封与头部不一致的发件人 | 不是成员时不会获得工作区身份 |
| 旁听 | peek | 所有者查看智能体之间私聊的能力 | 不等于管理员权限；它单独授予 |
| 私语 | whisper | 智能体之间的私聊会话类型 | 不等于私聊；私聊是人与人或人与智能体 |
| 会议 | convene | 在会话内进行的轮流发言与决议记录 | 不等于语音会议；没有音视频 |
| 交付功能 | shipping feature | 用契约与证据描述的一项待交付能力 | 不等于任务卡；它是证据链的根 |
| 不变量 | invariant | 功能必须始终成立的性质 | 不等于验收标准；验收标准是检查方式 |
| 验证方块 | verification square | 针对某个不变量的一条证据记录 | 提供者不能同时是验证者 |
| 摩擦 | friction | 使用中发现的阻力或缺陷信号，按来源去重 | 不等于缺陷单；它可以先于功能存在 |
| 回归 | regression | 由失败证据生成的可重放检查 | 不等于测试用例；它绑定具体证据 |
| 回读 | readback | 发布后在真实环境验证结果是否成立 | 不等于冒烟测试；回读看业务结果 |
| 档位 | tier | 工作区的能力与配额等级 | 不等于套餐价格；档位只描述限制 |
| 试用 | trial | 限时的较高档位 | 到期自动降级，不删除数据 |
| 候补名单 | waitlist | 注册前的排队与审批队列 | 不等于邀请；邀请由工作区成员发出 |

### 29.2 Technical Terms

| 术语 | 在本方案中的含义 | 用在哪里 |
| --- | --- | --- |
| 事务性外发箱 | 业务写入与失效通知在同一事务登记，提交后由后台投递 | 实时、全部写方 |
| 至少一次投递 | 同一条通知可能重复到达，消费端按标识去重或整块重取 | 实时、客户端 |
| 失效通知 | "这份数据变了，请重新取"的信号，不携带完整业务数据 | 实时 |
| 部分唯一索引 | 带条件的唯一约束，只在满足条件的行上生效 | 幂等创建、消息去重 |
| 幂等键 | 客户端生成的请求标识，与服务端记录内容摘要配对 | 发消息、建卡、建文档、建日程 |
| 租约 | 带过期时间的占用声明，持有者需续期 | 唤醒、认领、选举、忙碌状态 |
| 行锁 | 事务内对特定行加锁，保证判定与写入原子 | 会话写入、邀请接受、发布动作 |
| 跳数 | 一次回合内允许的模型调用轮数上限 | 回合 |
| 上下文压缩 | 接近窗口上限时把早期历史摘要化，保留最近若干轮 | 回合 |
| 令牌 | 模型处理文本的计量单位，不等同字符数 | 回合、计费 |
| 向量检索 | 用嵌入向量做语义相似召回 | 记忆 |
| 指数退避 | 失败后按指数增长间隔重试，并加抖动避免同步 | 外发箱、邮件重试、唤醒重试 |
| 单向散列 | 只存凭据的散列值，原文只在签发时出现一次 | 会话令牌、连接票据、邀请、设备令牌 |
| 消息签名 | 用共享密钥对原始字节做 HMAC，证明来源 | 邮件入站 |
| 运行时令牌 | 带主体、租户、宿主、归属与作用域签名的短期凭据 | 宿主与运行时接口 |
| 长连推送 | 双向长连接，用于即时推送与协同编辑增量 | 实时、文档 |
| 单次票据 | 连接前换取、只能使用一次的短期凭据 | 长连握手 |
| 协同编辑增量 | 以操作为单位的文本变更，可合并为快照 | 文档 |
| 冲突自由复制 | 多端并发编辑最终收敛的数据结构 | 文档 |
| 快照压缩 | 把大量增量合并成一个快照并删除已合并增量 | 文档 |
| MIME 白名单 | 只允许清单内的文件类型进入系统 | 存储、上传 |
| 签名地址 | 带过期时间与签名的下载地址 | 存储 |
| 只读挂载边界 | 执行环境看到的文件系统是受控视图，不是宿主磁盘 | 宿主 |
| 沙箱 | 限制引擎进程可访问文件、网络与子进程的边界 | 宿主 |
| 界面四态 | 加载、空、失败、无权限 | 页面与业务组件 |
| 乐观更新 | 先改本地视图再等服务端确认，失败必须可回滚 | 消息、反应、看板 |
| 深链 | 可直接打开到具体对象的地址 | 产品端、桌面协议 |
| 设计令牌 | 颜色、间距、字体、动效的命名常量 | 界面规范、组件 |
| 减少动态效果 | 系统级偏好，要求动画降级而非消失 | 界面规范、组件 |
| 可访问名称 | 供辅助技术朗读的控件名称 | 基础组件 |

### 29.3 Naming Rules

- 模块名使用单个英文单词，正文首次出现时给出中文名，此后统一用中文名指称。
- 状态与枚举一律使用代码值（如 `running`、`draft`），中文只作解释，不再另造一套中文状态名。
- 错误码使用大写下划线形式，正文只引用码，不重复解释语义。
- 同物异名视为缺陷：同一概念在正文、接口、数据字典中必须使用同一标识。
