## 22. Product Surfaces

本章说明同一份前端产物如何呈现五个界面壳：桌面、移动、Web、运营后台与桌面通知面板。页面只负责组装、导航与四态呈现，业务判定仍由服务端完成；界面壳不按角色划分，角色差异体现为入口可见性与服务端拒绝。模块边界与数据归属以 [总体方案与架构](./architecture/) 为准，房间与消息类型以 [Conversation](./modules/conversation/) 为准。

### 22.1 Surfaces

产品端共四个，另有通知面板一个附属表面。四个产品端共享设计令牌与服务端契约，但只有桌面与移动共享组件与状态存储，布局骨架各不相同；通知面板只共享令牌。

| 表面 | 服务人群 | 设备与入口 | 权限差异 | 形态差异 |
| --- | --- | --- | --- | --- |
| 桌面 | 以桌面为工作台的团队成员与所有者 | Electron 安装包；浏览器打开同一构建时以窗口卡片呈现 | 智能体私聊仅所有者可见；观察面需开发能力；智能体编辑与下线由服务端判定 | 44 px 标题栏、72 px 导航栏、可拖拽侧栏与单右栏组成三栏 |
| 移动 | 需要在手机上跟进会话、审批与查看工件的成员 | iOS 与 Android 原生壳；窄屏浏览器回退到移动布局 | 私聊标签仅所有者可见；推送状态与退出位于我的 | 100dvh 单列，三级栈导航，深层流程隐藏标签栏 |
| Web | 尚未安装桌面端的新用户与需要重新登录的用户 | `app.*` 域名或带 `webonly` 参数；PWA 清单 | 只处理公开登录与一次性交接令牌 | 只做登录、候补判决与协议交接，不渲染主应用 |
| 后台 | 平台运营与排障人员 | `admin.*` 域名或 `/admin` 路径 | 独立管理员判定，结果只有检查中、管理员、拒绝三态 | 独立样式表与侧栏，不复用主应用的 Tailwind 组件 |
| 通知面板 | 正在使用其它窗口的桌面用户 | Electron 第二个无边框透明窗口，固定于主屏右上 | 只显示当前用户是成员的会话通知 | 不导航、不承载页面，仅渲染通知栈并回传点击 |

各端的能力边界：

**桌面**承载全部十个业务视图与十六类壳级浮层，是唯一提供可调侧栏、单右栏与多面板并置的表面；它不提供移动端的全屏工件消费，也不提供后台的跨租户检索。

**移动**承载会话、私聊、会议、资料库、交付、智能体与我的等视图，用标签栏与三级栈替代桌面三栏；不承载观察面与后台。原生壳把所有字体覆盖为系统字体并关闭文字选择，消息行除外。

**Web**是刻意的极小表面：登录、候补判决、`cumora://auth` 交接三件事，成功后交给桌面端；它不提供会话列表，也不提供任何写入入口。

**后台**只有用户、候补、可观测、设置四页，以只读检索与少量特权操作为主；样式自成一体，登录后由管理员判定决定是否渲染。

**通知面板**只在主窗口失焦时出现，点击穿透由主进程按是否仍有通知切换；它不理解页面状态，只把点击回传为主窗口的"聚焦并选中会话"。

各端共享什么、不共享什么，决定了改一处会不会牵连另一处：

| 共享层 | 共享范围 | 说明 |
| --- | --- | --- |
| 组件与令牌 | 令牌各端共享；组件仅桌面与移动共享 | 颜色、间距、图标一致，布局骨架不共享 |
| 领域状态存储 | 桌面与移动共享，后台独立 | 视图与栈字段不同，数据源与刷新策略相同 |
| 实时通道 | 桌面与移动共享，Web 不建立 | 单连接去重，重连后重取当前会话 |
| 权限判定 | 四端一致，全部由服务端判定 | 前端只决定入口是否渲染 |
| 导航 | 四端各自实现 | 桌面内存视图、移动栈、后台路径、Web 片段 |

界面壳不按角色划分：成员、所有者与管理员使用同一套桌面与移动壳，差异只表现为导航项是否出现、按钮是否渲染以及服务端以 403 或 404 拒绝。唯一按权限整页切换的是后台，它要么渲染管理界面，要么停在拒绝页，不与租户面共享路由。

### 22.2 Desktop Pages

桌面视图由导航状态 `view` 单选，右侧槽位同一时刻只允许一个面板；视图条件挂载，因此草稿必须存在状态存储而不是面板内部。

| 页面 | 页面标识 | 导航状态 | 一句话功能边界 | 可用角色 | 主要操作 | 关键展示区域 |
| --- | --- | --- | --- | --- | --- | --- |
| 会话 | `page.conversations` | `view=conversations` | 统一消息流，附带一个上下文右栏 | 全部成员 | 搜索、筛选、选会话、发消息、引用、反应、建群、发邮件 | 320 px 侧栏、聊天头、虚拟列表、输入区、420 px 右栏 |
| 私聊旁听 | `page.whispers` | `view=whispers` | 只读旁听智能体之间的私聊 | 仅所有者 | 选一对私聊、读转写、查看检查器 | 私聊列表、转写区、检查器 |
| 站立会 | `page.convene` | `view=convene` | 进行中的实时会议，不做日程编辑 | 全部成员 | 开始、结束、看瓷砖、读转写 | 智能体瓷砖网格、转写、开始与结束按钮 |
| 智能体 | `page.agents` | `view=agents` | 名册与宿主引擎概览，详细配置在编辑器 | 全部成员可读，编辑受限 | 新增、编辑、下线、开聊、查看宿主与工具 | 页头、新增卡片、智能体网格、离线与离职徽标 |
| 看板 | `page.boards` | `view=boards` | 看板列表到列与卡片，含评论与截止日 | 全部成员 | 建板、改名、加列、拖拽移动、评论 | 列表栏、画布、卡片详情 |
| 日历 | `page.calendar` | `view=calendar` | 共享日程与智能体定时任务 | 全部成员，私密行过滤 | 前后翻月、新建与编辑事件、设重复与提醒、立即运行 | 工具栏、月与周网格、即将开始栏、事件编辑器 |
| 文档 | `page.documents` | `view=documents` | 文档列表与协同编辑 | 全部成员，按文档授权 | 新建、改名、删除、打开、编辑、提及、插图 | 280 px 列表、协同编辑器 |
| 交付 | `page.shipping` | `view=shipping`，懒加载 | 功能到发布证据链，不替代看板 | 全部成员 | 建功能、加不变量与验证、推进状态、发布、回读 | 主从工作区、证据面板 |
| 观察面 | `page.observability` | `view=observability`，需开发能力 | 回合轨迹、成本与工具载荷的只读排障 | 具备开发能力者 | 筛选运行、下钻、看成本与工具载荷 | 运行列表、下钻详情 |
| 我的 | `page.me` | `view=me` | 个人资料、用量、计算机、项目、信任与偏好 | 全部成员，部分区块仅所有者 | 改资料、看用量、配对与移除计算机、管理信任、切换偏好 | 六个标签、面板、守护进程过期横幅 |

四态要求逐页落实，不用空白代替无权限：

| 页面 | 加载 | 空 | 失败 | 无权限 |
| --- | --- | --- | --- | --- |
| 会话 | 列表与消息分别显示载入态 | 未选会话给出标题与副题；列表为空给出筛选提示 | 气泡标记失败或未确认，可重试；重试复用同一幂等键 | 非成员房间不出现，读写在服务端统一按不存在处理 |
| 私聊旁听 | 列表与转写分别载入 | `whispers.noWhispers` 说明没有可旁听的私聊 | 转写载入失败可重试 | 入口不渲染，直达接口返回 403 |
| 站立会 | 连接与转写载入 | 无进行中会话时给出开始入口 | 实时帧中断后重连并重取转写 | 不适用，全员可见；开始与结束由服务端判定 |
| 智能体 | 名册载入 | 网格保留新增卡片作为空态 | 名册载入失败可重试 | 编辑与下线被服务端拒绝并回显原因 |
| 看板 | 列表与画布分别载入 | `boards.emptyHint` 与新建按钮 | 乐观移动失败后重取快照 | 非成员看板不可见 |
| 日历 | 网格载入，事件单独载入 | 空日程给出新建按钮 | 网格错误行内展示，可重试 | 私密事件被过滤，表现为看不到而不是报错 |
| 文档 | 列表载入，编辑器单独载入 | `docs.empty` 与新建入口；未选文档给出选择提示 | 打开失败给出重试 | 未授权文档给出不可用说明 |
| 交付 | 懒加载回退文案 | 各段 `ship.*` 空态 | 载入与保存错误行内展示 | 状态推进由服务端拒绝并列出缺失项 |
| 观察面 | 运行列表载入 | 无运行记录时说明采集范围 | 查询失败可重试 | 能力不足时静默回到会话页，不用空白页 |
| 我的 | 每个标签独立载入 | 各标签独立空态 | 标签级错误与重试 | 所有者专属区块不渲染 |

桌面十个视图共享六条导航约束，页面实现不得自行发明：

- 右栏互斥：线程、资料、工件与邮件共用一个槽位，打开新面板即清空旧面板。
- 条件挂载：离开视图即卸载内容，输入草稿必须存在状态存储，不能留在面板内部。
- 懒加载：交付整页懒加载，加载期显示统一回退文案，不应出现空白画布。
- 能力门槛：观察面在开发能力缺失时静默回到会话页，不保留可见的空壳入口。
- 身份切换整树重挂载：切换用户或工作区时重建整棵组件树，旧租户数据不得闪现。
- 浏览器窗口化：同一构建在浏览器中以窗口卡片呈现，最大宽度 1480 px，不退化为移动布局。

十六类壳级浮层不进入视图树，也不改变导航状态；右栏同时只允许一个面板，打开新面板会清空旧面板，浮层按栈顶逐一关闭：

| 浮层 | 组件 | 触发 | 关闭规则 |
| --- | --- | --- | --- |
| 线程抽屉 | `ThreadDrawer` | 消息悬浮操作或回复数 | 关闭按钮、Escape、切换会话；占用右栏 |
| 成员与智能体资料 | `InfoPane` | 点头像或成员堆叠 | 再点触发点、Escape、切换会话；占用右栏 |
| 三个工件 peek | `DocumentPeekPane` `BoardPeekPane` `CalendarPeekPane` | 文档、看板卡、日程事件的链接或列表项 | 返回、Escape、切换会话；文档与看板使用 420 至 640 px 的弹性宽度 |
| 邮件抽屉 | `EmailComposer` | 新建邮件或回复邮件 | 发送成功、关闭按钮、Escape；发送失败留在抽屉内 |
| 智能体编辑器 | `AgentEditor` | 新增或编辑智能体 | 保存成功、取消、Escape |
| 日程编辑器 | `EventEditor` | 新建或编辑事件 | 保存成功、取消、Escape |
| 建群浮层 | `GroupCreator` | 侧栏新建群聊 | 创建成功、取消、Escape |
| 邀请成员浮层 | `InvitePeopleModal` | 邀请入口 | 发送成功、关闭、Escape |
| 工作区设置浮层 | `WorkspaceSettingsModal` | 工作区菜单 | 关闭、Escape；危险操作二次确认 |
| 投票编辑器 | `PollComposer` | 输入区斜杠命令 | 发布成功、取消、Escape |
| 图片查看器 | `ImageViewer` | 点击消息或文档图片 | 点击背景、Escape；缩放范围 0.1 至 12 倍 |
| 右键菜单 | `ContextMenu` | 桌面右键 | 选择项、点击外部、Escape；越界自动翻转 |
| 成员浮层 | `MembersPopover` | 成员堆叠 | 点击外部、Escape |
| 表情浮层 | `EmojiPopover` | 输入区表情按钮 | 选择表情、点击外部、Escape |
| 更新对话框 | `UpdaterDialog` | 发现更新或手动检查 | 稍后、关闭；安装阶段不可取消 |
| 即将上线提示 | `ComingSoonPop` | 点击未实现入口 | 知道了、点击外部、Escape |

### 22.3 Mobile Pages

移动端以标签和三级栈组织：会话内固定为列表、聊天、会话信息三层，私聊内固定为列表与房间两层；没有返回栈数组，栈层由单一字段表达。

| 屏幕 | 层级 | 功能 | 状态 | 手势与返回 |
| --- | --- | --- | --- | --- |
| 会话列表 | 标签，列表层 | 搜索、未读、静音、滑动操作、长按菜单 | 骨架载入、未读胶囊、静音铃铛、空态 | 下拉刷新；滑动快捷操作；点行进入聊天 |
| 聊天 | 三级栈第二层 | 转写、输入、回复与编辑、跳回最新 | 正在输入、失败重试、未确认 | 边缘右滑返回列表；标签栏隐藏 |
| 会话信息 | 三级栈第三层 | 成员、主题、文件、操作 | 分区空态 | 右滑回聊天；标签栏隐藏 |
| 私聊列表与房间 | 标签，两层 | 与桌面同构但更紧凑的旁听 | 空态说明与桌面一致 | 房间内右滑回列表；房间内隐藏标签栏 |
| 会议 | 标签 | 瓷砖、转写、开始与结束 | 无会话空态、已结束 | 标签切换；不进入三级栈 |
| 资料库 | 标签 | 文档、看板、日程三段与新建按钮 | 分段空态、创建中 | 标签切换；打开工件进入全屏 |
| 交付 | 标签 | 紧凑主从的证据链 | 懒加载回退、段级空态 | 标签切换；详情为全屏层 |
| 智能体 | 标签 | 智能体卡片与状态 | 空态 | 标签切换；点卡片进入参与者信息 |
| 我的 | 标签 | 工作区、资料、推送状态、外观、语言、退出 | 推送权限方块、外观与语言选中态 | 标签切换；退出需确认 |
| 参与者信息 | 全屏层 | 成员资料、工具、私聊入口 | 离线 | 右滑或关闭返回上一层 |
| 工件全屏 | 全屏层 | 文档、看板卡、日程事件的全屏消费 | 打开中、不可用 | 关闭返回来源屏幕 |

三级栈的规则：会话内 `list → chat → info` 只前进一层，进入信息层时列表以 30% 视差留在底层；跨标签切换用 140 ms 淡入，不用栈动画；每个标签内容包在独立的错误边界内，单个标签渲染失败不白屏。

手势返回规则：边缘拖动按速度提交，拖动距离不足或速度不够时回弹；返回动作只弹一层，不允许一次退两级；Android 硬件返回派发可取消事件，未被页面处理时才退出应用。

标签栏隐藏规则：会话栈不在列表层、私聊已选中房间、参与者信息或工件全屏打开时隐藏标签栏；返回列表层后恢复，隐藏与恢复都不改变标签选中项。

手势的判定与降级统一如下，避免同一手势在不同屏幕有不同阈值：

| 手势 | 判定 | 结果 | 减少动态效果时 |
| --- | --- | --- | --- |
| 边缘右滑 | 位移与速度共同判定，速度足够时提前提交 | 弹出一层 | 直接切换，不播弹簧与视差 |
| 下拉 | 超过臂长阈值并触发一次触感 | 重取列表 | 保留动画完成度，仅缩短时长 |
| 行左滑 | 超过动作区宽度 | 露出置顶、静音等快捷操作 | 动作区直接展开，无回弹 |
| 长按 | 450 ms 内位移不超过 10 px | 打开上下文菜单 | 菜单淡入改为瞬时出现 |
| 点击 | 按下即触发，不等抬起 | 触感加 0.97 缩放 | 去掉缩放，只保留触感 |

### 22.4 Entry and Auxiliary Pages

入口页面在壳之外，先于认证或先于工作区判定；它们只做一件事，不携带主应用的导航状态。

| 页面 | 触发条件 | 目标 | 关键状态 |
| --- | --- | --- | --- |
| 登录 | 无令牌且非 Web 域 | 第三方登录或服务器地址覆盖 | 跳转中、行内错误、服务地址可清除 |
| 邀请接受 | 链接或本地缓存中存在邀请令牌 | 预览并接受邀请 | 无效或过期、已是成员、需先登录 |
| 无工作区 | 已登录但无所属工作区 | 创建第一个工作区 | 输入自动聚焦、回车提交、错误行 |
| 配对引导 | 免费档且没有已配对计算机 | 在终端执行配对命令 | 生成中、复制成功或失败、轮换确认、等待连接 |
| 候补确认 | 地址带候补片段 | 显示候补判决 | 片段只消费一次，关闭后刷新 |
| 停用告知 | 地址带停用片段与原因 | 说明停用原因 | 片段只消费一次，关闭后刷新 |
| Web 落地 | `app.*` 域名 | 登录并引导打开桌面端 | 仅列出服务端声明支持的登录方式 |
| Web 交接 | 登录成功且已批准 | 触发一次协议交接 | 自动触发一次，可手动重新触发 |

入口判定按固定顺序短路，先命中的分支决定渲染哪个页面，后续分支不再求值：

```text
#notifications            通知面板，独立渲染器
地址片段 waitlist=1       候补确认
地址片段 suspended=1      停用告知
admin 域名或 /admin 路径  后台
邀请令牌                  邀请接受
Web 域名且非桌面壳        Web 落地与交接
无令牌                    登录
有令牌但无工作区          无工作区
免费档且无已配对计算机    配对引导
其余                      桌面或移动主壳
```

后台四页共用独立侧栏与顶栏，窄于 900 px 时侧栏收为抽屉：

| 页面 | 路径 | 功能 | 状态 |
| --- | --- | --- | --- |
| 用户 | `/users` | 搜索、档位筛选、分页、逐行改档位与管理员、停用 | 载入、错误横幅、行内确认 |
| 候补 | `/waitlist` | 批准或拒绝待审申请、刷新统计 | 空、错误 |
| 可观测 | `/observability` | 模型与智能体观测台、下钻弹窗 | 载入、下钻、相对时间 |
| 设置 | `/settings` | 候补开关与注册暂停两个全局开关 | 保存中、错误横幅、按下状态 |

后台的认证顺序是：先复用同一登录门，再请求管理员身份，得到检查中、管理员或拒绝；拒绝页只显示当前账号与退出登录，不显示任何管理数据。

### 22.5 Page Flow

页面流转以"来源、动作、目标、返回"四元组固定，避免同一入口在不同页面产生不同落点。

| 来源 | 触发动作 | 目标 | 返回行为 |
| --- | --- | --- | --- |
| 冷启动，已有令牌与工作区 | 完成引导判定 | 会话页 | 关闭窗口隐藏到托盘，不退出进程 |
| 冷启动，已登录但无工作区 | 创建第一个工作区 | 会话页 | 不可回到无工作区页 |
| 冷启动，免费档未配对 | 终端配对成功 | 会话页 | 引导页不再出现 |
| 登录页 | 登录成功 | 会话页 | 不保留登录页历史 |
| 邀请链接 | 接受邀请 | 会话页 | 加入的工作区出现在切换器，列表刷新 |
| 会话列表 | 选中会话 | 聊天面板 | 返回列表保留选中项与草稿 |
| 会话消息 | 打开线程 | 线程抽屉 | 关闭后回到原滚动位置 |
| 看板 | 点卡片 | 卡片详情 | 关闭回到看板原列与滚动位置 |
| 日历 | 新建或编辑事件 | 日程编辑器 | 保存后关闭、刷新并选中该事件 |
| 智能体 | 新建或编辑 | 智能体编辑器 | 保存后关闭、刷新并选中该智能体 |
| 观察面 | 开发能力被禁用 | 会话页 | 静默重定向，不提供返回入口 |
| 任意页面 | 退出登录 | 登录页 | 清空会话、工作区与配对状态，不可回退 |
| 桌面通知 | 点击通知 | 会话页并选中该会话 | 切回会话视图后保持选中 |

当前实现的导航状态全部存于内存：桌面用 `view` 加右栏标识，移动用 `view` 加 `mobileStack`，刷新即回到默认视图；只有后台使用真实路径。方案目标是把可分享、可恢复的状态写进 URL，把瞬时状态留在本地：

| 状态 | 现状 | 目标 | 判定 |
| --- | --- | --- | --- |
| 当前工作区 | 内存字段 | `/:workspace` 前缀 | 待确认前缀形式 |
| 一级视图 | 内存字段 | `/:workspace/:view` | 采用 |
| 选中会话 | 内存字段 | `/:workspace/conversations/:id` | 采用 |
| 选中文档、看板、事件 | 内存字段 | `/:workspace/documents/:id` 等三条资源路径 | 采用 |
| 线程根消息 | 内存字段 | `?thread=:messageId` | 采用 |
| 移动三级栈 | 内存字段 | `?stack=chat` 与 `?stack=info`，逐层可返回 | 待确认是否与桌面共用路由 |
| 搜索词与筛选 | 内存字段 | `?q=` 与 `?filter=` | 待确认 |
| 右栏 peek 开关 | 内存字段 | 暂不写进 URL | 待确认是否允许分享 |
| 输入草稿 | 本地存储 | 不进 URL，从本地恢复 | 采用 |
| 浮层开关 | 内存字段 | 不进 URL，刷新即关闭 | 采用 |
| 登录令牌与交接令牌 | 地址片段，只消费一次 | 永不进入可分享 URL | 采用，安全约束 |
| 后台路径 | 真实路径 | 保持 | 采用 |

深链恢复的边界：URL 只承载"看什么"，不承载服务端数据快照；恢复后按参数重新取数，权限不足时落到该资源的不可用态而不是空白页。刷新与前进后退可以重放转场，但转场不得改写 URL，也不得重复提交。标为待确认的条目是现状与目标的差异，确认前不进入实现。

### 22.6 Prototype Notes

本方案不附独立原型文件，以页面清单与组件伪代码为准。理由有三条：交付物是可导入 Astro 的 Markdown 内容集合，另建前端产物会形成第二份正文；原型一旦独立演进，会与页面标识、四态和权限表漂移；核心路径依赖实时通道、租约与服务端判定，静态演示无法可信复刻，做成"看起来能跑"的假交互反而会误导评审。

原型的边界写清楚：只做静态演示，不接真实接口；不伪造登录、推送与更新；不复刻实时协作与多人并发；不模拟服务端权限判定，只演示拒绝态的外观与文案。任何在原型中出现的成功态都必须在正文的页面表里有对应来源。

核心路径以页面清单加组装伪代码表达，下面的伪代码只说明壳如何选页、如何传参，不包含业务实现：

```tsx
// 页面组装只表达槽位与传参，不包含业务实现
// Page assembly expresses slots and props only, not business logic
interface ShellRoute {
  view: "conversations" | "whispers" | "convene" | "agents" | "boards" | "calendar" | "documents" | "shipping" | "observability" | "me"
  conversationId?: string
  boardId?: string
  meTab?: "profile" | "usage" | "computers" | "projects" | "trust" | "preferences"
  rightSlot: { kind: "thread" | "info" | "doc" | "board" | "calendar"; id: string } | null
}

function DesktopShell(props: ShellRoute) {
  return (
    <ShellFrame titleBar={<TitleBar />} rail={<Rail active={props.view} />}>
      {props.view === "conversations" && (
        <ConversationsLayout conversationId={props.conversationId} right={props.rightSlot} />
      )}
      {props.view === "boards" && <BoardsView selectedId={props.boardId} />}
      {props.view === "me" && <MeView tab={props.meTab} />}
    </ShellFrame>
  )
}
```

评审时的替代做法：按 22.2 与 22.3 的表格逐页走查，用 22.5 的流转表核对返回行为，用 22.7 的验收项判定是否可以交付；需要真实观感时以现有产品构建为准，不以本方案另造演示。
