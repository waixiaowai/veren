# @veren/im-ui

协作工作区的人机界面：一个侧栏面板——人在这里新建会话、往房间里写字并看着智能体回复、
二维码就在页面里扫码授权微信、账号与人员目录一眼看全、陌生人采集审计随手可查。

## 什么时候使用

只要有人（而不仅是 agent）需要在 Web 界面管理 IM，就随 `@veren/im-bundle` 一起安装。
headless、ACP、SDK profile 跳过——`im_*` 工具已覆盖全部操作。

## 面板内容

| 页签 | 内容 |
|---|---|
| 会话 | 全部房间的时间线；「新建会话」给所有者与默认智能体安排座位，输入区以 `human:owner` 写入，五秒轮询同时刷新列表与打开中的时间线，智能体的回复无需手动刷新即可出现。群聊的信息侧栏可以随时邀请人和智能体（`addMembers`）；私聊没有邀请入口，因为两个座位就是房间本身。回合运行期间，最后一条消息之下有一条不可交互的工作行，显示智能体的阶段（思考 / 调用工具 / 撰写回复）、已用时间与流式推理的末尾；回复落地即消失。未读数随同一次轮询到达、打开房间即清空；输入 `@` 打开键盘可达的成员选择器；每条消息有悬停复制；新消息只在读者位于底部时跟随，否则给出「回到最新」胶囊 |
| 智能体 | 从部署的 DSH preset 读出的名册（智能体就是 preset）：带计数的大标题、摘要芯片（智能体/会话/未读），每个智能体一张卡片，显示 preset id、会话数、最近活动与「聊天」动作（打开或新建私聊） |
| 账号 | 已授权账号与在线徽标、二维码绑定向导（发起、轮询、验证码）与解绑 |
| 人员 | 通讯录：按名字、别名、联系方式与备注搜索；手工新增联系人，编辑全部档案字段（名字、真名、别名、联系方式、简介、备注），删除前二次确认。手工联系人被渠道观察到之前没有可达地址，会被标注「仅档案」 |
| 设置 | 从日常路径里退出的两个 2.x 面：陌生人采集审计与 CMS 云端目录 |

## 布局

页面恰好占满面板盒子，绝不画到盒子之外。标题、刷新动作与页签条固定不动；四个文档页签在
页签条之下的同一个区域里滚动，长设置页因此是滚动而不是溢出窗口边缘被裁掉，最后一个控件
始终可点。会话页签是例外：它自己的两栏全高布局，由房间列表、时间线与信息侧栏各自滚动。

## 写入路径

面板是唯一以「人」的身份写入的表面。`imConv` 在读取方法旁暴露 `post`、`createRoom` 与
`addMembers`；三者都走会话服务，由它在提交后发出 `im/message-new`。这个事件正是唤醒
智能体的输入——渠道吸收、模型的 `im_send` 与输入区都汇入同一个扇出。

## 架构

纯浏览器插件（Node 半边是空 Loader 行）。浏览器半边手工挂载三个远端命名空间——`im`
（核心：账号、人员、采集、扫码绑定）、`imConv`（会话域：房间、成员、消息、写入、建房、
加成员、已读）与 `imTurn`（回合域的实时活动：`activity`）——渲染每五秒轮询的可观察对象；绑定
向导打开期间每两秒轮询，活动循环在有回合运行时 1.2 秒、没有时 3 秒。样式为 `.im-*` 手工
前缀 + 共享 `--dsw-*` 主题 token；文案 zh/en 双语带编译期 parity。
