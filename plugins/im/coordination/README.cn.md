# @veren/im-coordination

重设计后的 im 家族的仲裁域：确定性唤醒分流、低优先唤醒预算、按智能体的已见水位，以及
让多智能体房间保持体面的两道写入闸门（新鲜度与逐字）。

## 何时使用

当 im 家族需要「判定与拒绝」这一层时使用本包：谁被唤醒（以及谁刻意安静）、一条草稿还能
不能发出、拒绝的闸门把什么交还给作者以便改写。不要在这里产生内容——协调只产出判定。
也不要在其他任何地方启动回合：本包发出的 `im/wake-request` 是家族唯一的唤醒源。

## 它拥有什么

- 确定性分流：人类私聊唤醒房间的智能体；智能体之间的噪音失败关闭（除非被点名）；群聊
  保持安静（除非人类点名）。设计的廉价模型判断是已文档化的 v1 推迟。
- 低优先唤醒预算（每进程每分钟，默认 20）。
- 已见水位（存储域 `im_coordination`）：新鲜度闸门的基线；缺失的水位失败开放；水位只进
  不退。
- 写入闸门，经 `gatePost(...)` 交给 `conversation.post(input, gate)` 在会话写链内判定：
  新鲜度（拒绝并附最多 8 条未看到的消息）与逐字（拒绝折叠空白后的重复）。
  `preflightReply` 提供只读判定。

## 事件

- 发出 `im/wake-request` —— 回合启动的唯一合法途径。
- 消费来自 `@veren/im-conversation` 的 `im/message-new`。

## 配置

- `lowPriorityWakesPerMinute` —— 合成扇出预算（默认 20）。
