本方案以现有实现为事实基础，整理出一套可追溯、可验收的中文设计文档，覆盖总体架构、逐模块契约、接口、权限与多主体、错误码与状态模型、产品原型、UI 与组件设计及系统验收标准。

## 1. Project Overview

这是一个面向学习研究场景的多平台内容采集工具：使用者通过命令行或控制台面板，指定目标平台（七家主流中文内容社区）、采集模式（关键词搜索、指定内容详情、创作者主页）与数据保存方式，由系统驱动浏览器以真实登录态访问平台接口，抓取内容、评论与媒体文件，统一整形后落库或落盘。

目标用户是从事学习研究的人员：他们需要以可控频率批量获取公开内容的结构化数据，痛点在于各平台接口签名各异、登录态维护繁琐、数据格式不统一。系统以浏览器自动化保留登录态、以脚本注入方式取得签名参数、以统一存储适配屏蔽平台差异，并强制对人物标识做匿名化脱敏，落库数据不含可识别个人的字段。

核心架构按职责分为四层：控制层接收使用者意图（命令行参数或面板操作），以子进程方式拉起采集进程并回传日志与状态；采集层由平台爬取器承担主链路，内部依次完成登录凭证获取、签名参数注入、分页抓取与限频退避；存储层把各平台异构数据整形为统一实体，按所选介质落库或落盘；外围能力（媒体下载、代理池、缓存、词云）以旁路组件挂在采集层上，缺失不影响主流程。数据流向单向：平台接口 → 爬取器 → 存储适配 → 介质；控制流双向：控制层下发任务，采集进程回吐日志、状态与结果文件。所有数据变更权集中于存储适配层，采集层只生产不落地的中间数据。
