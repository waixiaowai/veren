## 9. UI Specification

本章为消费方界面定规范。取材只有一个真实来源：内建错误页的完整样式表（取证：`packages/better-auth/src/api/routes/error.ts:30-108`）——这是框架里唯一被消费方直接看到的视觉面，它的令牌、断点与动效就是本方案的 UI 基线；接口参考页的视觉由 Scalar 控件接管，不构成基线。适用范围分两类：**内建面**只描述已实现的事实；**消费方面**给出必须遵守的契约。页面归属见 [产品原型](./product/)。

### 9.1 Color and Semantic Tokens

以内建错误页为基线的语义令牌。这些令牌在错误页样式中以 CSS 自定义属性定义，浅色为默认，深色经 `prefers-color-scheme: dark` 覆盖：

| 令牌 | 语义 | 浅色值 | 深色值 |
|---|---|---|---|
| `--background` | 页面与卡片底色 | `white` | `oklch(0.15 0 0)` |
| `--foreground` | 正文与标题前景 | `oklch(0.271 0 0)` | `oklch(0.98 0 0)` |
| `--primary` | 主按钮底色 | `black` | `white` |
| `--primary-foreground` | 主按钮前景 | `white` | `black` |
| `--border` | 描边、分隔线、网格 | `oklch(0.89 0 0)` | `oklch(0.27 0 0)` |
| `--destructive` | 错误语义（`ERROR` 徽标边框） | `oklch(0.55 0.15 25.723)` | `oklch(0.65 0.15 25.723)` |
| `--muted-foreground` | 次要文案 | `oklch(0.545 0 0)` | `oklch(0.65 0 0)` |
| `--corner-border` | 四角装饰描边 | `#404040` | `#a0a0a0` |

两条取证到的缺口，消费方令牌表必须补齐：

1. 错误页的码芯片引用了 `var(--muted)` 但样式表从未定义它（取证：`error.ts:269`）——该声明在计算时失效、芯片实际无底色。消费方组件如果沿用"芯片底色"这个视觉，必须**显式定义 `--muted`**，不得依赖内建页的缺省行为。
2. 等宽字体令牌 `--default-mono-font-family` 的默认值指向 `var(--font-geist-mono)`，而后者同样未定义（取证：`error.ts:58`）——未定制时码芯片实际回退到正文字体族。消费方需要真正的等宽呈现时须提供自己的字体族令牌。

三类令牌是**消费方补充项**，框架错误页不含（依据：错误页只有错误一种语义，无成功、警告与禁用状态可供取证）：`--success`（成功语义，邮箱校验通过、口令重置完成）、`--warning`（警告语义，账号锁定倒计时、令牌即将过期）、`--focus-ring`（焦点环，错误页无键盘可达的表单控件故未定义）。焦点环在实际控件上必须有且可见，见 9.6。

### 9.2 Spacing and Typography

间距以 4px 为基准：错误页定义 `--spacing: 0.25rem`（4px），全页间距取其倍数——容器内边距 1.5rem（24px，6 步）、区块间距 1.5rem、芯片内边距 0.375rem 与 0.75rem（6px、12px，1.5 步与 3 步）、按钮内边距 0.5rem 与 1rem（8px、16px，2 步与 4 步）、卡片最大宽 42rem、次要文案最大宽 28rem（对应令牌 `--container-md`）。消费方表单页沿用同一标尺：控件高度、栅格沟槽、区块留白一律落在 4px 网格上，不出现奇数值。

字号档取错误页定义的四档，附断点降档（取证：`error.ts:44-50`、`95-107`）：

| 令牌 | 默认 | 不超过 640px | 不超过 480px | 用途 |
|---|---|---|---|---|
| `--text-sm` | `0.875rem` | `0.8125rem` | `0.8125rem` | 码芯片、次要文案 |
| `--text-2xl` | `1.5rem` | `1.25rem` | `1.125rem` | 页标题 |
| `--text-4xl` | `2.25rem` | 不降档 | 不降档 | 预留 |
| `--text-6xl` | `3rem` | `2.5rem` | `2rem` | `ERROR` 徽标大字 |

行高随档位内建：`--text-sm` 行高比 1.25 ÷ 0.875，`--text-2xl` 为 2 ÷ 1.5，`--text-6xl` 为 1。字重只用三档：medium 500、semibold 600、bold 700；正文用 500 以下不加粗（错误页正文段落无字重覆盖）。`ERROR` 徽标额外收紧字距 `-0.02em`——大写大字的通用处理，消费方标题可沿用。字体族：正文为系统栈 `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif`，等宽族缺口见 9.1。

### 9.3 Layout

内建错误页布局（取证：`error.ts:110-167`）：整页垂直水平居中，单张卡片承载全部内容——卡片 `max-width: 42rem`、宽度 100%、内边距 1.5rem、2px `--border` 描边、直角（按钮与卡片显式 `border-radius: 0`）；四角装饰为 2rem 见方的 4px 描边角标（`--corner-border`）；背景铺 40px 网格线并以径向遮罩把中心掏空保证卡片可读；徽标下有一条贯穿卡片的全宽 2px 分隔线。所有内容单列纵向排列，移动端靠字号降档而非布局重排适配。

消费方表单页布局建议：单列表单容器宽度对齐 `--container-md`（28rem），卡片化承载（描边与留白沿用 9.3 错误页参数），字段纵向排列、错误文案紧贴字段下方；列表型页面（会话、账号、用户管理）用表格或列表卡片，行内操作靠右；移动端列表退化为堆叠卡片，操作按钮整行铺开。桌面与移动共用同一套令牌，不做两套布局代码。

### 9.4 Micro-interactions

内建错误页的动效清单只有一条：按钮 hover 时透明度过渡到 0.8，时长 150ms、曲线 `cubic-bezier(0.4, 0, 0.2, 1)`（取证：`error.ts:55-56`、`75-80`）。这条动效同时定义了全局基准：时长 150ms、标准曲线 `cubic-bezier(0.4, 0, 0.2, 1)`。

消费方组件在此基准上的令牌化时长约定：

| 交互 | 变化属性 | 时长与曲线 | 可中断 | 降级 |
|---|---|---|---|---|
| 按钮 hover | opacity 至 0.8 | 150ms 标准曲线 | 是，双向过渡 | 减少动态效果时瞬变 |
| 提交中态 | 按钮换为 Spinner、禁用 | 状态切换 150ms；Spinner 旋转 800ms 线性循环 | 不可中断（请求在飞行） | Spinner 换静态省略号文案 |
| 口令显示切换 | 图标切换、输入类型切换 | 图标 150ms 标准曲线；类型切换瞬变 | 是 | 瞬变 |
| 复制确认 | Toast 滑入滑出 | 滑入 150ms、停留 2000ms、滑出 150ms | 滑出可被新 Toast 打断 | 瞬入瞬出，停留不变 |
| Dialog 开合 | 遮罩透明度、面板缩放 | 150ms 标准曲线 | 关闭可被 Escape 打断 | 瞬变 |
| 码输入格推进 | 焦点移动 | 焦点环 150ms | 是 | 瞬变 |

减少动态效果降级：媒体查询 `prefers-reduced-motion: reduce` 命中时，全部过渡与循环动画改为瞬变或静态呈现，停留时长与可中断性不变。动效只允许作用于 opacity、transform 与颜色，禁止触发布局重排的属性参与过渡。

### 9.5 Microcopy

按钮文案一律动词开头：`Sign in`、`Create account`、`Send reset link`、`Set new password`、`Revoke`、`Approve`、`Deny`、`Accept invitation`。危险动作用动词加宾语（`Revoke session`），不用"确定"这类无信息词。

错误提示三要素：发生了什么、为什么、下一步。例：口令登录失败不写"登录失败"，写"邮箱或口令不正确。请检查输入后重试，或使用忘记密码重置口令。"——同时不泄露账号存在性（等时失败统一码，见 [错误码](./errors/#54-retry-semantics)）。

错误文案来源是铁律：**不得在组件里内联写死文案映射**。服务端响应携带 `code` / `message` / `status`，客户端用 `$ERROR_CODES` 聚合面按码查文案（取证：`packages/better-auth/src/client/vanilla.ts` 导出 `$ERROR_CODES`），组件只渲染映射结果；`$ERROR_CODES` 未覆盖的码回退渲染服务端 `message` 原文。全部码的语义表见 [错误码](./errors/)。

空态文案给出下一步动作：会话列表空态写"当前没有其他活动会话"；绑定列表空态写"尚未绑定任何第三方账号"，并直接给出绑定入口。确认弹窗复述对象与后果："吊销这台设备上的会话？该设备的下次访问需要重新登录。"——按钮与标题用同一动词。

### 9.6 Accessibility

五条硬规则：

1. **对比度下限**：正文与背景至少 4.5:1，18px 以上大字与背景至少 3:1；基线令牌的浅深两套组合（`--foreground` 对 `--background`、`--muted-foreground` 对 `--background`）按此标准校验，消费方自定义令牌同样过检。
2. **焦点可见**：所有可交互元素有 `--focus-ring` 焦点环（建议 2px，颜色与背景形成至少 3:1 对比），键盘 Tab 顺序与视觉顺序一致，不得 `outline: none` 且无替代。
3. **图标按钮可访问名称**：口令显示切换、复制、吊销这类纯图标按钮必须有可访问名称（如"显示口令""吊销此会话"），图标本身不承担语义。
4. **表单错误与字段关联**：错误文案经 `aria-describedby` 关联到字段，`aria-invalid` 标记出错字段；校验在提交时统一触发，输入中不抢焦点。
5. **状态不得只靠颜色**：内建错误页是范本——错误状态由三重非颜色信号同时呈现：`ERROR` 徽标（文字）、`CODE:` 芯片（码原文）、描述段落（自然语言），红色仅是附加信号（取证：`error.ts:222-295`）。消费方的成功、警告、加载态同样必须带文字或图标信号，不得只换颜色。

### 9.7 Internationalization

内建面仅英文，这是事实而非疏漏：错误页声明 `lang="en"`、全部文案硬编码英文、无任何语言协商逻辑（取证：`error.ts:25` 及全文无 i18n 钩子）。消费方需要多语言时**自建错误展示页**：配置 `onAPIError.errorURL` 指向自己的错误页，承接相同的 `error` 与 `error_description` 查询参数，按用户语言渲染；内建页的 `customizeDefaultErrorPage` 只覆盖视觉令牌，覆盖不了文案。

消费方页面的本地化规则：错误文案从 `$ERROR_CODES` 取码后进宿主自己的文案表按语言映射；全部可见文案走文案键而非拼接句子（语序随语言变化）；布局为文案长度浮动预留空间——按目标语言集中最长者预留约三成伸缩余量，按钮不因德语类长词换行溢出，标签与输入上下排布以吸收长度差。

### 9.8 Icons and Illustrations

图标一律 SVG：单色、`currentColor` 取色、尺寸落在 16px、20px、24px 三档；语义图标固定一组（显示、隐藏、复制、警告、成功、关闭、外部链接），同一语义不复用两个图形。**禁止 emoji 充当图标或状态标记**：状态用 Alert、Badge 或文字徽标表达，禁止、勾选、警告一律走 SVG 语义图标或文字，不用符号字符；基线证据是内建错误页全文无一个图标与 emoji——错误状态完全由文字与描边承担。插画仅允许出现在空态与错误兜底页，单色线条风格，随 `--border` 与 `--muted-foreground` 取色，不引入位图。

### 9.9 Theming

明暗跟随系统：错误页以 `prefers-color-scheme: dark` 整段覆盖令牌（取证：`error.ts:82-94`），无手动切换开关。消费方沿用同一策略——默认跟随系统，宿主如需手动切换，在自己的应用层实现令牌组切换，框架不提供。

定制与覆盖面：内建错误页的视觉定制只能经 `customizeDefaultErrorPage`，覆盖三类——`colors`（背景、前景、主色、描边、错误色、次要前景、角标、网格、卡片底、标题）、`size`（四档字号与圆角）、`font`（正文族与等宽族），外加三个结构开关 `disableTitleBorder`、`disableCornerDecorations`、`disableBackgroundGrid`（取证：`error.ts:23`、`35-66`）。消费方组件的令牌覆盖走同名 CSS 自定义属性，组件内部不得写死色值。

切换不出现不达标中间态：主题判定（系统查询或宿主切换）必须在首帧渲染前完成，令牌整组原子替换；禁止先渲染浅色再补深色的闪烁路径，中途态的对比度不达标即违例。

### 9.10 Scrollbar and Media Rules

内建面不适用，依据如下：错误页是单屏静态文档，无滚动容器与媒体内容（`body` 仅整页 `overflow-y: auto`，无自定义滚动条样式，取证：`error.ts:110`）；接口参考页的滚动与媒体行为由 Scalar 控件内部管理，框架不介入。因此滚动条、图片、视频、音频规范对本框架的界面**无约束对象**。

消费方表单页适用常规规则：滚动条样式跟随主题令牌（轨道透明、滑块用 `--border` 与 `--muted-foreground` 之间取值），长列表（用户管理、会话列表）用虚拟滚动或分页而非无限增长；认证界面不承载图片上传与音视频播放，媒体规则仅在宿主业务区域生效，与本规范无交集。
