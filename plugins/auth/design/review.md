## 13. Review

本方案是**设计文档**：记录「设计已描述」，不等于「系统已通过验收」。本章记录假设、待确认项与实际校验结果。

### 13.1 Core Business Judgment

| 域 | 命中判据简证 | 存疑说明 |
|---|---|---|
| `context` | ① 所有能力经装配取依赖；② 装配失效无依赖可用；③ 仅留装配域仍可运行 | 无 |
| `endpoint` | ① 全部请求入口；③ 仅留路由域仍是完整路由校验系统 | ② 未命中——路由失效是"不可达"而非"失格"，故按①③入列 |
| `guard` | ① 非幂等请求必过守卫；② 失守则跨站伪造穿透 | ③ 未命中（砍掉仍可跑但不安全），按"①且②"入列 |
| `identity` | ①②③ 全命中 | 无 |
| `credential` | ①②③ 全命中 | 无 |
| `session` | ①②③ 全命中 | 无 |
| `storage` | ① 全部状态落地；② 一致性根基（原子原语） | ③ 未命中，按"①且②"入列 |

**比例核对**：核心 7 ÷ 全部 16 = **0.44**，超出 0.1–0.4 建议区间上沿。原因与裁决见 [1.4.3](./architecture/#143-ratio-check)：协议框架的业务本身就是判定链，粒度偏细所致；接受该比例并以核心域深化要求补偿（铁律成文、失败分支伪代码、验收 ≥4 条）。
