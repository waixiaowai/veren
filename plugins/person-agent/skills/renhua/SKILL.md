# 人话

好读不是写得少，是读者花得少。省字省过头会变成电报体：每个字都重要，读者却要自己补关系、补背景、补语气。人读的时候，重复是缓冲，铺垫是扶手。先让读者跟得上，再谈简洁。

## 写之前：给读者一个位置

开头三句话：这篇讲什么，读者现在在哪，往下会看到什么。不要从盘古开天辟地讲起，从读者关心的那个点开始。

## 六条规矩

1. **开头先给位置感。** 讲什么、读者在哪、往下按什么顺序看。
2. **每段只做一件事。** 自检：给这段起一个五字标题；起不出来，就拆开。
3. **拆掉壳。** 把"进行/通过……的方式/对……加以"换成动词开头。动词打头，名词具体，数字代替形容词。"对配置进行修改"改"改配置"；"在很多情况下"改"常常"；"性能有较大提升"改"快了 3 倍"（有数字才写数字）。
4. **长短句交替呼吸。** 长句承载关系，短句落钉。一句里超过三个逗号，拆；连续三个短句，补一句关系。
5. **顺序就是逻辑。** 先发生、先重要、先读者要做的。别靠"因此/然而/综上所述"串联；真转折才用一次。
6. **给眼睛落脚点。** 小标题、序号、对照表。人是先扫后读，不是从第一个字读到最后一个字。

## 写完之后

**技术正确不等于读者在意。** 结尾回答："所以我该干什么？"——下一步、截止时间、要找谁、要不要回复。

**改稿只有一个办法：读出声。** 卡住的地方、换气不顺的地方、要回头重读的地方，就是读者会卡的地方。

## 一条分工线

给机器读的可以省到骨头；给人读的省修辞，不省语境。
无论多短，否定词、条件、数量、代码/路径/报错原文一律不动。删掉"不""仅""除非""至少"或改掉一个数字，意思就变了。

英文写作同理：动词开头，短句，具体名词；不要为了简短丢掉必要语境。

## 什么时候不该用

给 agent 看的紧凑指令、列表型数据、代码/API 参考、日志和表格，不要套这套。它们要的是密度和结构，不是阅读节奏。技能正文、工具描述、参数 schema 也不适用。
