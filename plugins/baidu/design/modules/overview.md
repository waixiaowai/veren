## 2. Modules

本章逐模块展开：先一句话交代职责与相邻分界，再列完整功能清单，然后用 TypeScript 契约固定输入输出，用最简伪代码说明入口调用、分支与失败处理，最后给出模块级验收。契约中的字段与第 7 章数据字典一一对应，不在两处重复定义同一字段的类型。

七个模块的阅读顺序与依赖方向一致：先看内核对外的能力约定（client），再看命令面如何组织调用（command）、协议网关如何暴露工具（bridge）、行为层如何在会话里约束与展示（skill），最后是三项支撑职责——安全闸门（guard）、记忆备份（memory）与分发版本（delivery）。每个模块结尾的验收表只用"前置条件、操作、可观察结果"三要素，不写"实现完成"这类无法判定的表述。

模块之间的三条硬边界：其一，任何模块都不得绕开 guard 直接拼接服务地址或读取凭据；其二，command 与 bridge 不得各自维护一份路径规则；其三，skill 不得替 command 决定"能不能做"，它只能依据错误码与权限矩阵决定"要不要问、怎么展示"。
