# @veren/person-agent-reanchor

[English](README.md) | 中文

## 概述

管家会话本该只做判断和派活，但长对话会漂移：人设挂在系统提示词最远的头部，工作记忆快照会变旧，桥梁于是开始自己读代码、自己写文件。本插件就是定期重锚：它读会话日志，当尾部出现**连续 N 步只做检查/分析、期间没有派活**时，把一条关于这个事实的短提醒追加到下一次模型请求。

提醒是**只追加的会话消息**，通过 `agent/pre-step` 决策加入。它从不改写系统提示词，因此 exact-prefix 缓存不受影响：`deepseek-v4-pro` 没有声明 `systemPromptUpdate: 'in-history'`，中途原地改提示词会让每一步重付全部历史。

会话本来就该自己动手时不要装它；它是给「派活的桥梁」用的，不是给工作会话用的。

## 触发条件

每个步骤边界，插件从日志尾部向前扫描：

- 工具调用按 `(turn, step)` 分组。
- 一步里**所有**调用都在 `analysisTools` 里，这一步才算分析步。
- 遇到第一个含其他调用的步骤、人类输入、或上一条重锚提醒就停止计数（因此两条提醒之间至少隔着 N 个新的分析步，不会每步复读）。
- **本回合**里已经派过活，则完全不提醒；上一回合派过活不算，因为本回合仍在自干。
- 派活次数仍会扫描整个会话，提醒里可以如实说明本次会话是否派过活。

提醒引用实时数字（连续步数、分析调用数、不同 `file_path` 数、派活次数），在三种措辞间轮换，长度约一百多 token。连续两条提醒不会逐字相同。

## 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 设为 `false` 不注册监听器，插件整体关闭 |
| `threshold` | `3` | 触发一条提醒所需的连续纯分析步数 |
| `analysisTools` | `read`、`read_image`、`glob`、`grep`、`web_search`、`web_fetch` | 只做检查/分析的工具 |
| `dispatchTools` | `session_dispatch` | 把活交给其他会话的工具 |

管家预设以 `withReanchor: true` 挂载本行，并把 `reanchorThreshold` 传进来。在预设行上设 `withReanchor: false` 会整行摘掉；把本插件的 `enabled` 设为 `false` 则保留行但关闭行为。工具列表为空、阈值非正数时在加载期显性失败。

## 模型体验

提醒是一条用户角色消息，来源 kind 为 `person-agent-reanchor`，`form: 'notice'`，并带一行摘要供 UI 展示。它追加在宿主已准入消息之后，是模型决定下一步前读到的最后一条输入。触发时约增加一百多 token，其余步骤为零。

#### KV 缓存影响

不影响缓存前缀：系统提示词保持静态，提醒追加在既有历史之后。插件刻意不贡献系统提示词区块。

## 已知限制与后续工作

- 分析集合按工具名判定。别的组合改了工具名后，需要同步更新 `analysisTools`，否则不再算分析。
- 没有工具调用的步骤会打断连续段；插件不从助手文本猜测意图。
- 提醒只是陈述事实，不能强制模型派活。真正不听话的模型仍然没有 `edit` 工具可用，那是另一层结构性防线。
- 插件刻意无状态：每一步重读日志。连续步数在连续段断开处停止，但全会话的派活数与提醒数仍要遍历日志；两者都只是数组读取，相对一次模型请求很便宜，但开销随日志长度线性增长。

## 开发

```bash
pnpm install
pnpm build
pnpm test
```

测试包含一个脚本化假适配器驱动的 30 步、约 42 万字符会话：装插件时第 4、7……28 步出现重锚，不装时一条都没有。
